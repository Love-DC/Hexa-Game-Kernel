### 3.2 跨规范同义映射

| Save §3.4（权威） | 完整项目规范 §6.2 | Project Architecture §7 | 处置 |
|---|---|---|---|
| Save Format Version | Save Format Version | save file format | 同义 |
| World Schema Version | Kernel State Schema Version | world-state schema | 同义（用 §3.4 名） |
| Mod Schema Version | Mod Data Schema Version | Mod-owned persistent schema | 同义（`mods[].schema_version`） |
| Platform Version | —（§6.2 无） | Runtime version | **映射并入**（`platform_version` 涵盖 Runtime） |
| Kernel API Version | API Version | Kernel API version | 同义 |
| Mod Version | —（§6.2 无） | Mod code version | 同义（`mods[].version`） |
| —（不在 §3.4） | Game Definition Version | — | **元数据字段**（`game_definition.version`，见 §3.2） |
| —（不在 §3.4） | — | Migration implementation | **非存档元数据**（迁移实现标识，归 `SAVE-006`） |

> **Q-F4-a 结论（R-2）：** `Runtime version` 不新增为独立 Manifest 字段；以 `platform_version` 承载并无损映射并入。此为本任务按"最小字段集"的落地；如需并列 `runtime_version`，属 Save §3.4 扩展，须另行授权。

## 五、独立工程任务 ENG-DEP-BOUNDARY-01（F-3 落地）

- **任务名：** 依赖边界自动检查（Dependency-Boundary Check）
- **依据：** `Project Architecture v1.0.md` §4.4（L465，MUST automate dependency-boundary checks）；`Game Kernel — 完整项目规范 v1.0.md` §2.2（L174）。
- **现状（核实）：** 无 `deny.toml`、无 `tests/architecture/`、无依赖方向检查代码。**任何验收不得假定该检查已存在。**
- **目标：** 提供最小、可运行的自动化检查，防止环依赖与越界依赖。
- **最小验收标准：**
  1. 存在自动化检查（如基于 `cargo metadata` 的测试或脚本），可被本地门禁/CI 调用。
  2. 断言 `kernel-core` **不依赖**任何平台 crate（当前即 `platform-core`、未来 `save-manager`）。
  3. 断言 workspace **无依赖环**。
  4. 当引入违规依赖（负例）时检查**失败**；无违例时**通过**（含负例测试）。
  5. 不修改既有生产代码语义；`SAVE-001` 等实现可复用该检查。
- **时机：** 建议在 P4 新建 crate（`save-manager`）**之前或同时**完成；本任务**不实现**。
- **登记：** `planning/02` **GAP-26**；`planning/22` §九 列为 P4 前置事项。
