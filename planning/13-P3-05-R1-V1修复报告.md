## 1. V-1 是否真正修复

**是（对 `id()` 不稳定这一类，已真实闭合）。**

V-1 的根因链：阶段一预校验读取的是 `declared_id`；阶段二 `Kernel::register_system` **再次**调用 `System::id()`（一次校验、一次查重、一次排序）并以其返回值作为注册身份。由于 `System::id()` 没有任何稳定性约束，一个在预校验期间返回合法值、在注册期间返回非法值的 `System`，可以通过阶段一，在阶段二被 Kernel 拒绝——而此时批内更早的元素**已经被 push 进 Kernel 并写入协调器记录**，形成部分注册。

修复方式：**在阶段一读取每个 System 的 `id()` 恰好一次并冻结**，阶段二把一个 `FrozenIdSystem` 包装器交给 Kernel；该包装器的 `id()` 恒返回冻结值。因此 Kernel 的校验、查重、排序所见的身份**永远是阶段一预校验过的那个身份**，`id()` 漂移无法再影响 Kernel。修复不修改 Kernel，不削弱任何测试，不缩小验收标准。

**已用外部探针独立复验**：修复前可稳定复现部分提交的那段输入（元素 0 正常 + 元素 1 首次 `id()` 合法、后续非法），修复后探针断言「全有或全无」通过，且 `/illegal` 未泄漏到 Kernel 或记录。

**残余边界（如实声明，非本次修复遗漏）**：若目标 Kernel 已存在**绕过协调器**直接注册的 System，协调器记录不知情，预校验仍会通过，Kernel 可能在批次中途拒绝某元素，从而留下更早元素。该残余路径属于**既有的旁路限制**（不是 `id()` 稳定性问题），已由测试 `residual_bypass_contamination_is_reported_not_hidden` 显式记录，并在 `ModRegistry` 文档中写明「不是无条件原子性承诺」。

## 3. 修复前后的关键执行路径

### 修复前（`lib.rs` 旧 `register_batch`）

```
阶段一（对 systems 借用切片 iter_mut）：
  for (index, (declared_id, system)) in pending.iter_mut().enumerate():
      if declared_id != system.id()                 // 读 id() 第 1 次
      seen.insert(declared_id)                       // 去重基于 declared_id
      self.registered.contains(declared_id)          // 历史冲突
      validate_type_id(declared_id)                  // 校验 declared_id
阶段二：
  for (index, (declared_id, system)) in pending.into_iter().enumerate():
      kernel.register_system(system)                 // Kernel 内部再读 id()（第 2+ 次）
      self.registered.insert(declared_id)            // 用 declared_id 记录
```

问题：阶段二 Kernel 读到的是 `id()` 的**后续**返回值，可能与阶段一的 `declared_id` 不同 → 阶段二可失败 → 更早元素已提交（部分注册）。

### 修复后（`lib.rs` 新 `register_batch`）

```
阶段一（消费 systems，构建 pending: Vec<(frozen_id, Box<dyn System>)>）：
  for (index, (declared_id, system)) in systems.into_iter().enumerate():
      let actual_id = system.id().to_owned();        // 读 id() 恰这一次，立即冻结
      if declared_id != actual_id                    // 与冻结值比较
      seen.insert(actual_id.clone())                 // 去重基于冻结值
      self.registered.contains(&actual_id)           // 历史冲突
      validate_type_id(&actual_id)                   // 校验冻结值
      pending.push((actual_id, system))              // 冻结值与 System 成对前移
阶段二：
  for (index, (frozen_id, system)) in pending.into_iter().enumerate():
      let frozen = Box::new(FrozenIdSystem::new(frozen_id.clone(), system));
      kernel.register_system(frozen)                 // Kernel 只看到冻结的 id()
      self.registered.insert(frozen_id)              // 记录与 Kernel 同源
```

关键：`FrozenIdSystem::id()` 返回 `&self.id`，无论 Kernel 调用多少次，返回值恒为阶段一冻结值 → Kernel 的校验/查重/排序身份与预校验身份**严格同源**。

## 7. 是否仍存在未解决的保证缺口

**存在，且已如实记录，不属于本次修复范围：**

1. **残余旁路类部分注册**：目标 Kernel 若含绕过协调器直接注册的 System，批次可能在更早元素已提交后于中途失败。此路径无法在不改 Kernel的前提下消除（协调器无法发现外部直调），已在 `ModRegistry` 文档与 `residual_bypass_contamination_is_reported_not_hidden` 测试中显式披露。**建议由后续阶段通过架构或工程规则处理（对应复核报告 G-4）。**
2. **`System::id()` 仍无稳定性契约**：本次修复使协调器**不再依赖** `id()` 稳定性，但 Kernel 自身的 `sort_by(left.id().cmp(right.id()))` 等操作仍假设稳定性。**建议后续为 `System` trait 补充 `id()` 稳定性要求（对应复核报告 G-5）。**
3. **规范缺口 G-1/G-2/G-3/G-6**（`Failed` 恢复、`Unloaded` 重载、`Disabled` 语义、全局一致性强制机制）：与 V-1 无关，仍未定义，待后续阶段统一处理。

**结论**：V-1（`id()` 不稳定导致的部分注册）已真正闭合；协调器不再以全称量词作无条件原子性承诺，措辞已收窄并与实现能力一致。
