## 8. 报告必答 8 问

1. **当前项目实际能做什么？** 一个确定性、可快照/恢复、可回滚的 Tick 驱动内核（实体/资源/命令/事件/System 调度），外加最小 Mod 平台：清单与包校验、依赖解析、锁文件复验、生命周期状态机、批量注册、受限 Wasm 宿主（2 个 Host API）、14 类故障报告结构、机器可读 API 目录，以及一个端到端 headless 演示。
2. **哪些能力已被测试证明？** §0 表中 129 项测试覆盖的全部能力（确定性、哈希、回滚、解析稳定性、锁复验、生命周期、冻结身份、故障码/决策、trap 映射、权限/导入、内存上限、路径逃逸），及 demo 的 `verified=true`。
3. **哪些能力只是设计或部分实现？** 存档/迁移/原档保护、确定性检测、迁移检测、Mod↔Mod 接口、隐性依赖、规模化、联机、SDK/Launcher、安全/性能——多为设计或规范，未实现；权限模型与 API Registry 为部分实现。
4. **原有架构能否支撑大量 Mod 组成的大型游戏？** **方向正确但尚未证明。** Kernel 最小化、宿主接口白名单、依赖解析 + 锁文件 + 生命周期 + 冻结注册的骨架与目标一致；但当前接口面仅 2 个、无 Mod↔Mod 接口、无规模化证据。**架构未被证伪，但"支撑大量 Mod"仍是待验证命题。**
5. **AI 能否独立开发和维护单个 Mod，并可靠协调跨 Mod 修改？** 单 Mod：**基本可以**（规范 + 清单 + 生命周期 + 自动测试）。跨 Mod：**尚不可以**（无 Mod 间接口、无跨 Mod 依赖影响分析与回归）。
6. **距离目标还缺哪些必要能力？** 存档/迁移系统（P4）、Mod 间接口与跨 Mod 回归、隐性依赖检测、规模化验证、联机（P5）、SDK/Launcher（P6）、安全/性能（P7）、确定性/迁移检测。
7. **哪些问题必须在正式完成前解决？** 存档与迁移正确性及原档保护、确定性/迁移检测落地、Mod 间接口兼容规则、跨 Mod 回归自动化、规模化证据、规范缺口（终态语义、注册旁路）。
8. **哪些问题可留待后续迭代？** 跨 OS 逐位确定性扩展、Launcher 体验、社区试用、原生模块、热加载、300+ 基准的方法与调优等。

## 9. 结论与建议

- **架构方向判断：** 现有"最小 Kernel + Mod 平台 + 白名单宿主接口 + 依赖解析/锁文件/生命周期/冻结注册"体系与项目根本目标一致，**未发现必须推翻架构的证据**。当前差距集中在**能力面（接口太少）**与**未实现的领域（存档/迁移、互操作、规模）**，属"推进"而非"重构"。
- **P3 结论不变：** 有条件通过（C-1 已满足；C-2 进 P4 核对 GAP-13/24/25；C-3 P3-05/06 无独立构建记录、经 #16 验证）。

  1. P4 任务卡制定：以已入库的 `Save & Compatibility Specification v1.0.md` 为领域基线，首包覆盖存档格式、迁移事务、原档保护、故障验收，并显式引用 GAP-13/24/25 与 C-2/C-3。
  2. 将"Mod↔Mod 接口 + 跨 Mod 回归"列为 P4/P6 的能力验收项（当前为最大结构缺口）。
  3. 归档 #19～#22 CI 结果；修正 R-8（`planning/19` §9.3 过时表述）。

### 10.3 保留的系统边界与风险

- SAVE-002 已批准的 B-3 明确规定 Mod 存档载荷为不透明字节，P4 不提供通用 Mod 持久化读写 Host API。当前 Save System 能安全保存、加载、备份、迁移和保留调用方提供的 Mod 分区，但 P3 Mod guest 尚不能通过通用 API 自行读写该分区；此前登记的 GAP-29/`planning/28` 仍应作为后续能力跟踪，不得以 P4 完成掩盖。
- SAVE-010 的 extractor 是受信任平台适配接口；缺少 payload 格式知识时会 fail-closed，不会猜测、自动重定向或静默忽略引用。
- 本机未测试 Linux、NFS/SMB/其他文件系统、掉电耐久或真实空间耗尽；任务卡的磁盘空间/进程中断场景是可控故障注入，不是硬件级保证。
- 没有大规模 Mod 基准、长期多版本样本集或 UI/Launcher 工作流；这些不属于 P4 当前批准的实现边界。
- 未生成本轮 Gitee Go 远端构建证据。P4 本地门禁全绿；远端验证要在用户决定推送工作区变更后再确认。

### 10.4 结论更新

与 P4 任务卡 `planning/22` 对照，SAVE-001～012 的批准契约实现、专项测试、§15.3 11 类恢复断言、GAP-24/25 的 SAVE-007 执行接线，以及四条本地最终门禁均已满足，**P4 本地验收通过**。历史 §4、§6、§8、§9 的 P4 未实现/下一步建议仅是 2026-10-14 基线记录，现由本补记替代。

此结论限定于 `planning/22` 当前 P4 边界；不表示 P3 Mod 持久化读写 API、P5 联机、P6 Launcher、P7 安全/规模/性能已实现，也不构成 Gitee Go 或跨平台验收。
