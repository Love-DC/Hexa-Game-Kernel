## 1. 范围与边界

**SAVE-004 = 一致快照与正常保存。** 本包负责：在 Tick 提交后的静止点获取内核快照，组装存档容器，生成完整性摘要，将容器经"临时文件 → 同步 → 验证 → 原子替换"流程落盘，并返回结构化提交结果。

**模块边界：** 在既有 `crates/save-manager` 内新增落盘模块（不新建 crate）；`crates/kernel-core` 仅新增 C-1 只读接口 `registered_system_ids()`。

## 3. 容器格式（DC-1）

- 存档落盘形态为**单文件容器**；文件内容逐字节等于 `SaveLayout::to_bytes()` 的 SAVE-002 v1 规范编码（tag `SL` + u8 版本 + u32 大端计数 + 规范序分区条目）。
- 物理字节 ≡ 逻辑规范字节 ⇒ SAVE-003 的摘要域（`GKSAVE-PARTITION-DIGEST-v1` / `GKSAVE-ROOT-DIGEST-v1`）无需为容器另设字段；提交时单次 `rename` 完成整档切换。
- 已明示代价：无局部恢复能力（Save §12.3 的局部损坏定位为校验层能力，不提供部分读取）；每次保存全量重写。

## 4. 一致快照与调用方输入责任（C-3 / B-1 / DC-7）

- 快照仅在 **Tick 提交后的静止点**获取（C-3，`Kernel Contract v1.0.md` §7）；`step`/`snapshot` 互斥由 Rust 借用规则保证；跨线程同步为调用方责任，内核不新增同步机制。
- 世界分区负载 = `Kernel::snapshot()` 原样字节（SAVE-002 裁决 B-1），保存层不解析、不映射其格式版本。
- `last_saved_at` 等时间戳由**调用方供给**（DC-7）；保存层不读取系统时钟。
- `simulation_config`：无确定性相关配置时写入空对象为合法；键命名纳入受控命名空间（R-6 落地）。

## 5. 系统清单（C-1 / C-2）

- `kernel-core` 新增只读接口 `pub fn registered_system_ids(&self) -> impl ExactSizeIterator<Item = &str>`（C-1），顺序 ≡ 执行序 ≡ ID 字典序。
- 清单以 `SM` v1 负载写入 `metadata/session-data` 分区（C-2）：tag `SM` ‖ u8 版本 = 1 ‖ u32 大端 `count`（≤ 4096）‖ `count` ×（u16 大端长度 ‖ UTF-8 ID）。单 ID 字节长度 1..=128（对齐 `validate_type_id`）；ID 字典序且唯一；**空清单（count = 0）与缺失负载必须可区分**；解码先验证 `count × 3 ≤ 剩余字节` 再分配。
- 演进规则：v1 负载 = 单一 `SM` 记录且其后存在任何字节即格式错误；负载内版本自描述，不新增 Manifest/Schema 级版本字段。
- 错误码：`save.system_manifest_missing`（负载/分区缺失）、`save.system_manifest_invalid`（tag/版本/截断/非法 UTF-8/重复或乱序 ID/超限）。
- 加载侧验证不在本包（归 SAVE-005）。

## 6. 正常保存流程

映射 `Save & Compatibility Specification v1.0.md` §11.2（步骤对应关系见括注；DC-3 裁决的操作顺序已并入）：

1. 静止点获取 `Kernel::snapshot()`（§11.2 步 1）。
2. 经 C-1 接口取系统清单，编码 `SM` v1（§11.2 步 4 的一部分）。
3. 组装初始 `SaveLayout`：Manifest / World / Mod / Metadata 分区，以及 **Integrity 分区**（占位负载，如空负载）。占位 Integrity 负载的内容不进入根摘要计算域（`canonical_view` 排除该分区），但该分区必须存在——`generate` 以缺失为结构性错误。
4. SAVE-003 `generate` 生成完整性摘要：返回 `{root, checksums}`，**不负责写回**。本流程将 `root` 写入本地 Manifest 副本的 `integrity.root_hash`，以 `checksums` 重建 Integrity 分区负载（§11.2 步 5）。
5. `SaveLayout::validate()` 验证布局（`generate` 与 `to_bytes()` 内部已各自强制执行校验，此步为最终布局的显式确认）。
6. 编码容器字节（SAVE-002 v1，`to_bytes()` 自带校验）。
7. 在正式存档**同目录**创建临时文件（§7），写入全部字节。
8. 对临时文件执行 `sync_all()`（§8）。
9. 读回临时文件字节，重新解码并按 SAVE-003 `verify` 校验（§11.2 步 7）。
10. `rename` 原子替换正式存档（§9，§11.2 步 8）。
11. 返回结构化提交结果（§10）。

**步骤 9（更新成功保存记录）不在本包实现**——其持久化设计（承载位置、文件格式、更新机制）为独立后续事项（§16），本包不得擅自决定。

> **状态：已批准并入（2026-10-18，`INTERFACE-APPROVAL-02`）。** 本节处理 `CONTRACT-AUDIT-01` 一般问题 1–3（入口签名、成功结果、`IoStage` 取值），消除编码前接口自由度；占位负载与流程措辞经 `INTERFACE-CHECK-02` 核查后按 `INTERFACE-APPROVAL-02` 指令修正（§6 步 3-4、§6.1.1）。除本节与 §10 的对齐修订外，契约其余内容不受影响。

### 6.1.1 入口签名（最小方案）

```rust
pub fn save(
    target: &Path,
    manifest: &SaveManifest,
    world_snapshot: &[u8],
    mod_partitions: &[SavePartition],
    system_ids: &[&str],
) -> Result<SaveOutcome, SaveError>
```

裁决问题逐项对应：

| 裁决问题 | 答案 |
|---|---|
| 目标路径如何传入 | `target: &Path`；临时文件在同目录派生（§7） |
| `Kernel::snapshot()` 结果如何传入 | `world_snapshot: &[u8]`——调用方在静止点自行调用（C-3 责任在调用方）；保存层不持有 `&Kernel`，世界负载保持 B-1 不透明 |
| Manifest 如何传入 | `manifest: &SaveManifest`（SAVE-001 已冻结模型直传，字段全 `pub`）；`integrity.root_hash` 允许占位，但占位值必须符合 SAVE-001 格式校验——64 位小写十六进制且不得为 `"IMPLEMENTATION_GENERATED"`（可采用 64 个 `0`），非法占位将在本流程以 SAVE-001 校验错误失败；本流程按 SAVE-003 生成后将真实 `root` 写入本地 Manifest 副本并重新序列化最终布局 |
| Mod 分区如何传入 | `mod_partitions: &[SavePartition]`（SAVE-002 已冻结类型直传；调用方以 `SavePartition::new(SavePartitionId::Mod(ns), payload)` 构造） |
| 时间戳由谁提供 | **非入口独立入参**：经 `manifest.created_at` / `manifest.last_saved_at` 字段由调用方供给（DC-7）；保存层不读系统时钟 |
| 返回类型 | `Result<SaveOutcome, SaveError>`（§6.1.2 / §10） |

系统清单：`system_ids: &[&str]`——调用方经 C-1 `registered_system_ids()` 收集；本流程负责 SM v1 编码与校验（§5）。空切片 = 空清单（`count = 0`）。

**被否决的备选**：调用方传入已组装的 `SaveLayout`——会迫使本流程拆解重建布局，并把"占位 `root_hash`"约定与 SM 编码细节泄漏给调用方；分区构造不变量无法内聚。本方案由保存流程全装配，无新增状态、无新依赖（仅复用 SAVE-001~003 已冻结类型与 std）。

### 6.1.2 成功提交结果（最小字段集）

```rust
pub struct SaveOutcome {
    /// Byte length of the verified container (read back before commit).
    pub bytes_written: u64,
    /// The final SAVE-003 root digest recorded into the Manifest.
    pub root_hash: String,
}
```

- `Ok(SaveOutcome)` 的返回**本身**断言两档事实：**内容已验证**（临时文件读回 + `verify` → intact）与**正式文件替换已成功**（`rename` 返回 Ok）。
- 两档的**失败区分**由 `SaveError::{Verify(..), Io{stage, ..}}` 分层承载（§10）；成功路径两档必然同真，故不携带恒 `true` 布尔（"不新增重复状态"纪律）。
- 本类型**不出现、不暗示**第三档（掉电后持久化）的任何表述（§8 约束 4/5）。

### 6.1.3 `IoStage` 取值（逐项依据）

`pub enum IoStage { Create, Write, Sync, Readback, Rename }`——与 §6 流程的五个 I/O 动作一一对应，无扩展：

| 取值 | 对应流程动作 | 批准依据 |
|---|---|---|
| `Create` | 临时文件 `create_new` 创建（含并发撞名 `AlreadyExists`） | 排他创建（DC-6/DC-11 机制）的错误出口；契约必要具体化 |
| `Write` | 临时文件写入 | 落盘 I/O 基本动作；契约必要具体化 |
| `Sync` | `sync_all` | **DC-3 已批准**（`DECISION-APPROVAL-01`） |
| `Readback` | 读回临时文件 | 与 `Verify`（摘要不匹配）分层：I/O 错误 ≠ 内容损坏；契约必要具体化 |
| `Rename` | 替换正式存档 | 旧档保护失败路径的报告点（§9）；契约必要具体化 |

**清理失败不新增取值**：错误路径上的临时文件清理为尽力而为；清理失败不产生新错误阶段，残留文件归 SAVE-007 孤儿清理（§7）。

### 6.1.4 `SaveError` 分层（类型级定义）

```rust
pub enum SaveError {
    Manifest(SaveManifestError),          // SAVE-001 原样传播
    Layout(PartitionError),               // SAVE-002 原样传播
    Integrity(IntegrityError),            // SAVE-003 结构性错误原样传播
    Verify(IntegrityReport),              // 读回摘要不匹配（非结构性）
    SystemManifest(SystemManifestError),  // SM v1（§5 两码）
    Io { stage: IoStage, path: PathBuf, source: std::io::Error },
}
```

- **实现偏差（已审查接受，`GK-P4-SAVE-004-POST-IMPLEMENTATION-AUDIT-01`）**：实际实现将 `Verify` 载荷装箱为 `Verify(Box<IntegrityReport>)`，原因是 `IntegrityReport` 超过 Clippy `result_large_err` 门禁的 128 字节阈值。装箱仅改变内存表示：错误信息完整携带（`Display` 输出 `manifest_root` 与 `computed_root`），错误分类与分层语义不变。
- 风格与 SAVE-001~003 一致（手工实现 `Display`/`Error`/`code_str`；save-manager 现有错误均为手工类型，**不新增 thiserror 依赖**）。
- `SystemManifestError` 两码的保存路径可达性：`Invalid` 可达（本流程必须校验调用方传入的 `system_ids`：单 ID 长度 1..=128、字符集对齐 `validate_type_id`、字典序唯一、`count ≤ 4096`）；`Missing` **保存路径不可达**（保存总是写出清单；空切片 = 空清单 `count = 0`），其定义保留给 SAVE-005 加载侧检测旧档缺清单。

### 6.1.5 与 SAVE-001~003 的兼容性核对

- **SAVE-001**：`SaveManifest::to_bytes()`（确定性序列化）产出 Manifest 分区负载；写回仅修改 `integrity` 成员（字段全 `pub`，合法）；传入 manifest 复用既有 `validate()` 双轨校验。
- **SAVE-002**：`SaveLayout::new` 自动规范排序、`to_bytes()` 自带校验、`from_bytes` 用于读回；`SavePartitionId::{Manifest, World, Mod, Metadata, Integrity}` 五变体与 §6 流程一一对应；不改 SAVE-002 任何已冻结接口。
- **SAVE-003**：`generate(&SaveLayout) -> GeneratedIntegrity { root, checksums }`（不写回）→ 本流程将 `root` 写入 Manifest `integrity`、`checksums` 作为 Integrity 分区负载；读回后 `verify` + `is_intact()`；M-α 哨兵自洽性保证写回后 `verify` 一致。
- **kernel-core**：`Kernel::snapshot()` 结果作为不透明字节传入；C-1 `registered_system_ids()` 尚未编码（编码授权发放前不存在），本提案不改变其已批准签名。

## 7. 临时文件（DC-6）

- 命名：`'.{name}.tmp-{pid}-{seq}'`，`seq` 来自进程内 `AtomicU64` 单调计数；与正式存档同目录（构造上保证同卷，`rename` 不跨文件系统）。
- 创建必须使用 `create_new` 硬排他（本机探针 C5：撞名返回 `AlreadyExists(os 80)`，先写者内容完好）。
- 清理只删除本调用创建的确切路径；**绝不 glob 删除**（防误删并发写者的临时文件）。孤儿临时文件的判定与清理归 SAVE-007。

## 8. 同步与耐久性（DC-3 = 方案 B，附 7 条裁决约束）

1. **正常流程顺序**：组装容器 → 生成完整性摘要 → 验证布局 → 创建同目录临时文件 → 写入 → `sync_all` → 读回并验证 → 替换正式存档 → 返回提交结果（即 §6）。
2. **`sync_all` 失败**发生在正式文件替换之前：必须清理本次创建的临时文件，保留旧正式存档，并返回结构化 `IoStage::Sync` 错误。
3. **替换前失败必须保留旧存档**；替换失败的保证以目标平台实际语义为依据（§12），**不得宣称所有文件系统均具有无条件的原子替换保证**。
4. **三档区分**（契约文本与返回语义均不得混淆）：
   - **内容已验证**：临时文件读回后通过 SAVE-003 `verify`（CI 可证）；
   - **正式文件替换已成功**：`rename` 返回 Ok，此后读取者看到新档（CI 可证）；
   - **掉电后数据持久化**：**不承诺**（CI 不可证，登记为平台风险）。
5. 本方案**不执行父目录同步，不承诺掉电耐久**。`sync_all` 只表示请求并完成操作系统所提供的同步语义，**不得将其等同于绝对的掉电存活保证**（存储设备易失写缓存、RAID/SMR 等行为不在保证内）。
6. 不新增结果保证等级字段；不引入提交日志、备份、孤儿文件清理或故障注入框架。
7. **同步失败路径的自动化测试缺口明确登记**（§14、§16）：当前无故障注入缝（注入机制归 SAVE-008，需独立裁决），`sync_all` 失败分支在本阶段以代码审查保证，是否引入故障注入机制另行裁决。

## 9. 正式文件替换与旧档保护

- 替换 = `std::fs::rename(temp, target)`。
- **旧档保护硬要求**（Save §11.2 步 8 / §11.5）：保存失败不得覆盖最近一次确认成功的正式存档。替换前任何阶段失败（布局/摘要/IO/Sync/Verify）⇒ 临时文件已清理、旧档字节不变。
- 平台语义依据（DESIGN-02 探针与官方文档，2026-10-15）：本机探针证实替换失败时旧档保留（C2 只读目标、C3 目录目标）；POSIX `rename(2)` 文档化"atomically replaced"与失败保留；Windows 在 Win10 1607+ 且文件系统支持 `FileRenameInfoEx` 时行为与 Unix 相同，`MoveFileExW` 回退路径的原子性未被文档化 ⇒ **替换原子性按平台实际语义声明，不夸大**。
- 已知排除：NFS 明确不保证（rename(2) 文档）；ReFS/exFAT/FAT32/SMB/overlayfs/APFS 未验证，登记为平台风险。

## 10. 错误分类

保存结果的错误侧为结构化分层（DC-4 方向）；类型级定义与逐项依据见 §6.1.3/§6.1.4：

- **Manifest / Layout / Integrity**：SAVE-001/002/003 既有错误类型原样传播，不改写、不包裹。
- **系统清单**：`save.system_manifest_missing` / `save.system_manifest_invalid`（§5；保存路径可达性分析见 §6.1.4）。
- **`Io{stage, path, source}`**：`stage ∈ {Create, Write, Sync, Readback, Rename}`（`Sync` 经 DC-3 批准；其余四项为契约必要具体化，逐项依据见 §6.1.3，经 `INTERFACE-FREEZE-01` 补充裁决冻结）；`path` 为涉及路径；`source` 为底层 `std::io::Error`。
- **Verify**：临时文件读回后摘要校验未通过，携带 SAVE-003 `IntegrityReport`（结构性错误仍走 Err 传播）。

## 11. 并发语义（DC-11 = S1）

- 同路径并发保存：**最后成功提交者胜**。
- 必须明确记录：**没有逻辑顺序保证**（最后提交者按墙钟序而非 tick 序），**可能出现静默丢更新**；调用方需要顺序保证时必须自行串行化。
- 跨进程协调不属于本阶段范围（登记为 SAVE-007 或独立后续决策）。

## 12. 平台保证边界

| 能力 | Windows | POSIX | CI 可证性 |
|---|---|---|---|
| 替换成功（rename Ok ⇒ 新档可见） | Win10 1607+ NTFS 与 Unix 同语义；旧版/回退路径原子性未文档化 | `rename(2)` 文档化原子替换 | **可证**（正常路径） |
| 替换失败 ⇒ 旧档保留 | 探针 C2（只读目标）/C3（目录目标）证实 | `rename(2)` 失败保留语义；Linux 可用 chmod 目录确定性注入 | **可证**（E-9 三分，§14） |
| 临时文件排他创建 | 探针 C5（`AlreadyExists`）证实 | `create_new` 同语义 | **可证** |
| `sync_all` 调用与错误传播 | `FlushFileBuffers` | `fsync` | 调用存在性可证；**失败路径无注入缝，登记为缺口** |
| 掉电后数据持久化 | 不承诺（NTFS 元数据日志为 FS 特性，非应用保证） | 不承诺（目录项未同步；ext4 data=ordered 等为 FS 特性） | **不可证，平台风险登记** |
| 其他文件系统 | ReFS/exFAT/FAT32/SMB 未验证 | NFS 明确排除；overlayfs/APFS 未验证 | 不可证，登记 |

纪律：测试断言只针对"CI 可证"行；"掉电持久化"不得以"`sync_all` 被调用"冒充通过。

## 13. crate 级 I/O 纪律（DC-10）

- `writer.rs` 是 SAVE-004 **唯一允许执行存档文件 I/O 的生产模块**。
- crate 级纪律测试扫描 `crates/save-manager/src/` 下**其他生产 Rust 文件**，禁止出现：`std::fs`、网络 I/O（`std::net`）、`std::process`、`unsafe`。
- **系统时间相关调用纳入检查**，但允许经明确批准的例外清单（避免误伤现有合法代码）；例外须逐项登记于测试注释或契约附录。
- 实施纪律测试**前**先核查现有代码及测试结构，确认规则可执行且不与既有合法行为冲突，再实施。
- **不得为通过扫描而随意移动、删除或重写现有代码**；发现冲突时停止并报告。

## 14. 测试要求

- 正常保存往返：保存 → 读回分区与 Manifest → SAVE-003 `verify` 通过。
- `SM` v1：编码往返、空清单、缺失清单、截断/未知 tag/未知版本/重复乱序 ID/超上限逐项拒绝（稳定错误码）。
- 旧档保护（E-9 三分）：E-9a Windows 只读属性作用于真实旧档文件（集成级）；E-9b Linux 单元级 `chmod` 目录 0o555 后 rename 失败注入；E-9c 目录目标降级为行为学测试（错误映射 + temp 清理），不计入旧档保护证据。三不变量：字节（len + sha256）/ 摘要（verify → Intact）/ 可读取性（from_bytes + verify 成功）；旧档须先经保存成功产生，再以不同内容触发失败。
- 并发：临时文件 `create_new` 排他负例；并发 temp 不冲突；S1 语义（后提交者胜、无撕裂数据）在进程内可测范围验证。
- `registered_system_ids`（C-1）：顺序与注册集合一致、反映增删、只读无副作用。
- I/O 纪律测试（§13）。
- **登记缺口**：`sync_all` 失败路径无注入缝，本阶段不可自动化测试（§8 约束 7、§16）。
- 门禁：`cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace`、`cargo run -p game-platform -- demo`（demo `verified=true` 不覆盖本包功能，仅作回归）；golden vector 与既有测试零变更通过。
