## 2. 端到端各环节的实际覆盖证据

测试文件含 2 个测试；主测试 `new_package_flows_through_the_full_platform_chain_to_execution` 覆盖 8 环节：

| # | 环节 | 真实覆盖证据（非占位） |
|---|---|---|
| 1 | **新建 Mod 包** | `ScratchDir::write_package` 在 `target/p3-integration-tests/` 下**真实写盘** `mod.json` + `module.wat`（测试内联构造 WAT 源码，**不复制既有 fixture**）；随后 `discover_mods` 从该目录发现，`packages.len()==1`。 |
| 2 | **包校验** | 正例：新包通过 `discover_mods`（内含 Manifest Schema + 语义校验）。反例：另建含 `unexpected_field` 的包，`discover_mods` **必须返回 Err**，证明校验是真闸门。 |
| 3 | **Resolver** | `resolve_load_plan(&packages)` 产出 `LoadPlan`，断言 `plan.mods[0].id == healthy_id`。 |
| 4 | **锁定/验证** | `plan.to_lock_file().write_to(lock_path)` 写真实 `mod-lock.json` → `LockFile::read_from` 读回 → `verify(&packages)` **重新校验磁盘包** → 得到 `verified_plan`；断言 `config_digest` 与 `mods` 一致。 |
| 5 | **权限授权** | `LoadedWasmMod::compile(pkg, &grants(), &engine)`；grants 为两个 Host API 权限（`world.read`/`world.command`），compile 内部执行 deny-by-default 检查。 |
| 6 | **加载/激活** | **加载身份派生自 `verified_plan`**：`locked_id = verified_plan.mods[0].id`（断言 `mods.len()==1`）；以 `locked_id` 选包并 `compile`；`ModLifecycle::discovered(locked_id)` → `Validated` → `Resolved` → `Loaded`（断言 `state()==Loaded`）；`ModRegistry::register_batch(&mut kernel, vec![(locked_id, system)])`，断言 `contains(&locked_id)` 与 `registered_count()==1`。 |
| 7 | **执行** | 3 次 `kernel.step`，断言 `counter==3`、`tick==Tick(3)`；快照后继续一步断言 `counter==4` 并记录 `expected_hash`。 |
| 8 | **故障诊断/恢复** | 恢复：`Kernel::from_snapshot` + 重新 `register_batch`（用 `locked_id`）+ 断言 `restored_registry.contains(&locked_id)` 与 `registered_count()==1` + 一步，断言 `resumed_hash == expected_hash`（快照重建复现无中断哈希）。诊断：另建 `unreachable` 陷阱包（真实写盘），执行时返回 `KernelError::SystemFailed`，断言稳定码 `platform.mod.guest_trap.unreachable`、`ModFaultReport::from_system_error` → `FaultCategory::WasmTrap`/`FaultPhase::Execution`/`Disposition::Stop`/`!retryable`/`tick==Some(0)`/`content_digest` 对齐；并断言故障 tick **未留下部分写入**（`counter==0`、`tick==0`）且后续 `KernelError::Faulted`。 |

第二条测试 `locked_package_that_changed_after_locking_is_rejected_before_registration`：锁定后篡改模块字节，`LockFile::verify` **必须拒绝**（`PlatformError::LockFile`），证明锁定是执行链上真实闸门。

**满足授权的强约束**：新建包为测试代码真实写盘（非 fixture 冒充）；锁定信息显式进入执行链并**因果驱动加载身份**（`locked_id` 派生自 `verified_plan.mods[0].id`，用于选包、`compile`、`ModLifecycle` 与 `register_batch`，不再使用字面量）；诊断/恢复与执行处于同一集成流程。
