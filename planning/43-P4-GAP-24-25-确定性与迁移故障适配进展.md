## GAP-24：确定性违规

新增 `MigrationDeterminismMonitor`：在同一进程中按 Mod ID、迁移器 ID、调用方提供的完整规范化上下文摘要关联输出摘要。相同键观察到不同输出时返回结构化 `DeterminismViolation`，可生成 `platform.mod.determinism_violation` 的 Schema 合法故障报告。容量耗尽和非法身份显式报错，不把“未观察”报告为通过。

运行时边界：首次观测只建立基线；只有相同完整上下文的后续观测才能发现分歧。Wasm runner 对每个步骤创建两个隔离 Store 重复运行，输入上下文包含 ABI 版本、模块代码 SHA-256、完整描述符和完整规范 JSON 输入；无导入 ABI 不提供时钟、随机数或宿主状态。观测到不同输出时返回稳定 `platform.mod.determinism_violation` 并沿事务错误路径保留原档/报告回滚状态。monitor 仍是同进程有界观察，不构成跨进程/跨平台证明。

## GAP-25：迁移失败故障报告

`game-platform` 现在依赖 `save-manager`，新增 `ModFaultReport::from_save_migration_error`，将 SAVE-007 `TransactionError` 转为 `platform.mod.migration_failed`，携带 Mod ID 和明确的恢复结果。故障类别映射、报告 Schema 验证和错误码测试均覆盖。

端到端边界：SAVE-007 现在直接调用 `WasmMigrationRunner`；Fuel 用尽用例实际经过 Wasm → `MigrationRunner` → SAVE-007 事务错误 → Platform 报告，验证原档仍可加载且回滚字段为成功。恢复状态仍由完成事务恢复判定的调用方传入报告函数。
