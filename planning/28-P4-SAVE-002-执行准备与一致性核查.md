### 2.4 版本映射事实登记（B-1 落地；**不得混为同一版本**）

> **事实（已批准记录，GK-P4-SAVE-002）：** `world_schema_version`（Save 规范 §3.3 示例 `"1.0"`，形式 `MAJOR.MINOR`）与 Kernel 世界的快照格式版本 `SNAPSHOT_FORMAT_VERSION: u32 = 2`（`crates/kernel-core/src/lib.rs:12`，**私有 const**）**目前没有映射关系**。
>
> - 二者**语义不同**：前者标识「世界数据 Schema 版本」（Save 侧治理，用于存档兼容性声明）；后者标识「Kernel 快照物理编码版本」（Kernel 侧治理，例如 `SnapshotEnvelope` 的线格式）。
> - **不得**把 `world_schema_version` 当作 `SNAPSHOT_FORMAT_VERSION` 的等价物；**不得**相互推演、相互校验，或把二者合并为单一字段。
> - SAVE-002 对世界分区采取 **B-1 方案**：**原样承载** `Kernel::snapshot()` 返回的字节，**不解析、不映射**任何版本；`world_schema_version` 仅作为由 Manifest 携带的**声明值**记录，与分区内容**不做一致性推断**。
> - 该映射缺失登记为独立待办（候选 `GAP-27`；`planning/02` 补登**待授权**）；其闭合**不属于** `SAVE-002` 范围。

- **不改：** `kernel-core`（B-1）、`platform-core`、既有 Schema/测试/规范、`planning/22` 受控状态。

### 3.2 交付能力（已随裁决冻结，逐项可测）

| # | 能力 | 说明 |
|---|---|---|
| 1 | **分区标识** | `SavePartitionId`：`Manifest` / `World` / `Mod(ModId)` / `Metadata` / `Integrity`，与 §3.1 五类一一对应 |
| 2 | **所有权模型** | `PartitionOwner`：`SaveSystem` / `Kernel` / `Mod(ModId)`；强制「Mod 分区只能由其自身命名空间拥有」 |
| 3 | **命名空间** | `ModNamespace` 复用 `identifier` 规则（与 Mod Manifest `mod_id` **逐字一致**，见 C-1）；拒绝 `/`、`..`、绝对路径、空段、大写 |
| 4 | **分区容器** | `SaveLayout`：有序分区集合；每分区携带 **owner + 命名空间 + 内容载体 + 可选 Schema 版本**；排序按命名空间**确定性**（不依赖哈希迭代序） |
| 5 | **未识别分区无损承载** | 保留**原始命名空间 + 原始字节**，标记「未识别 → 交由兼容性策略」；**策略本身不实现**（归 `SAVE-005`）——落实 §4.4 |
| 6 | **与 Manifest 一致性检查** | 分区命名空间集合 ↔ `SaveManifest.mods[].id`：**缺失 Mod 分区保留不删**（完整规范 §6.4）、多余分区登记为未识别；不在本期判定兼容性 |
| 7 | **确定性序列化** | `to_bytes` / `from_bytes` 往返**逐字节一致**（沿用 SAVE-001 已冻结方式） |
| 8 | **稳定错误码 + JSON Pointer** | 沿用 SAVE-001 风格（如 `save.invalid_partition` / `save.invalid_namespace` / `save.partition_ownership_violation` / `save.duplicate_partition`；**具体命名在实现时冻结并纳入契约测试**，对齐 SAVE-001 先例） |

> **B-1 / B-2 / B-3 落地要点（内容载体）：** 世界分区内容 = `Kernel::snapshot()` 的**原样字节**（SAVE-002 不解析、不映射版本）；Mod 分区内容 = **不透明字节**；`metadata/session-data` 归 `PartitionOwner::SaveSystem` 不透明承载，**不新增版本字段**。`integrity/checksums` 仅**承载**，摘要生成归 `SAVE-003`。
> **B-4 落地：** `save-manager` 维持**严格无 I/O**（落盘归 `SAVE-004`；无磁盘/网络/系统时间依赖）。

## 五、验收标准（已随裁决冻结范围；逐条可测）

1. **分区完备**：五类分区与 §3.1 逻辑结构**一一对应**；`manifest` 分区与 SAVE-001 `SaveManifest` 一致，不重复建模。
2. **命名空间正确**：每个 Mod 分区命名空间 = 稳定 Mod ID，格式与 Mod Manifest `mod_id` **逐字一致**；非法输入（含 `/`、`..`、绝对路径、空段、大写、非 ASCII）**稳定拒绝**并给出 JSON Pointer。
3. **所有权约束**：Mod 分区只能由对应 Mod 命名空间拥有；跨命名空间拥有被稳定拒绝。
4. **未知数据无损**：未识别分区往返**逐字节一致**；「加载 → 重新序列化」不丢失原始字节（§4.4 / §16.5）。
5. **缺失 Mod 保留**：Manifest 未包含的 Mod 分区**默认保留**、不被静默删除；无对应分区的 Manifest Mod 条目不被静默"补造"（完整规范 §6.4）。
6. **确定性**：分区排序与序列化**往返逐字节一致**；不引入磁盘/网络/系统时间/哈希迭代序依赖。
7. **错误契约**：错误机器可读（稳定码 + JSON Pointer）；文案不作为协议。
8. **不破坏既有工程**：`kernel-core` 仍**无任何平台 crate 依赖**；workspace 构建、既有 163 项测试、demo 行为不变。
9. **文档边界**：模块文档明确「仅分区模型与校验；无 I/O / 摘要 / 迁移 / 兼容性策略」。
10. **不得声明未实现能力**：任何未实现项不得计入验收通过项（沿 `GAP-24`/`GAP-25` 教训）。
