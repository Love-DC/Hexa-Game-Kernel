## 1. SAVE-008 / Save §15.3 故障注入追踪

| Save §15.3 故障 | 注入方式 | 原档恢复断言 | 验证测试 | 限制 |
|---|---|---|---|---|
| 磁盘空间不足 | 测试专用 seam 在写阶段返回 `ErrorKind::StorageFull` | 旧档字节相同，仍可加载校验；无临时文件 | `simulated_disk_full_is_reported_at_write_and_preserves_old_save` | 模拟 OS 写入错误；未真实填满磁盘 |
| 文件写入失败 | 测试专用 seam 在写阶段返回 I/O 错误；另测备份临时路径碰撞 | 五个保存 I/O 阶段故障后旧档字节相同且可加载；备份源及碰撞文件不变 | `injected_io_failures_at_each_commit_stage_preserve_previous_save`、`existing_backup_temp_file_simulates_exclusive_write_failure` | 不声称模拟真实设备 I/O 行为 |
| 文件截断 | 将备份文件截断后执行恢复 | 当前正式档原字节相同且可读，损坏备份保留待诊断 | `corrupt_or_mismatched_backup_is_refused_without_overwriting_target` | 针对恢复输入截断 |
| 校验和不匹配 | 篡改备份容器字节及 Mod 分区候选数据 | 源档及目标档字节相同、重新加载成功 | `checksum_mismatched_backup_is_refused_and_both_live_saves_remain_recoverable`、`corrupted_mod_partition_is_rejected_without_touching_the_confirmed_save` | 字节级篡改，不覆盖真实玩家档 |
| 提交前中断 | 构造日志处于 `CommitStarted` 且候选已就绪后调用恢复 | 候选被判定提交时原始备份字节仍相同且有效；恢复不重跑 migrator | `recovery_promotes_ready_candidate_without_reexecuting_migrator` | 确定性协议状态模拟，不是杀进程测试 |
| 提交后中断 | 正式目标已是候选，日志仍在最终记录前，调用恢复 | 候选保持完整，原档备份仍字节相同且可加载 | `recovery_recognizes_candidate_committed_before_final_journal_record` | 确定性协议状态模拟，不是掉电测试 |
| 迁移器崩溃 | Wasm guest 无限循环耗尽 Fuel | SAVE-007 拒绝提交，正式原档字节相同且可加载；Platform 诊断报告确认回滚 | `wasm_runner_failure_becomes_rollback_confirmed_platform_diagnostic` | Wasmtime trap/Fuel 模拟，不杀宿主进程 |
| Mod 数据损坏 | 篡改 Mod 分区载荷，再调用加载/校验 | 未损坏正式档保持字节相同且可加载 | `corrupted_mod_partition_is_rejected_without_touching_the_confirmed_save` | 完整性层拒绝损坏候选 |
| 依赖 Mod 缺失 | Compatibility Resolver 对真实文件档执行兼容判定 | 报告阻止加载；档案字节相同且可加载 | `a_missing_mod_is_blocked_with_missing_dependency` | 无迁移事务启动 |
| 迁移链不完整 | 真实文件档构造目标版本，但注册表无迁移边 | 计划构建失败于事务开始前；档案字节相同且可加载 | `incomplete_migration_chain_is_rejected_before_any_source_write` | 无迁移器执行 |
| 恢复备份损坏 | 截断/篡改备份后请求恢复 | 正式目标不变且可读；源档不变且可读 | `corrupt_or_mismatched_backup_is_refused_without_overwriting_target`、`checksum_mismatched_backup_is_refused_and_both_live_saves_remain_recoverable` | 真实文件副本上的内容故障注入 |

注入钩子仅存在于 `writer` 私有实现与 crate 单元测试中，不导出为生产 API。所有磁盘内容断言只使用测试生成的有效存档，不接触玩家数据。

## 2. SAVE-006/007 受限 Wasm 迁移 ABI v1

- 执行入口为 `game_platform::migration_runtime::WasmMigrationRunner`，实现 `save_manager::transaction::MigrationRunner`；SAVE-007 继续持有事务、备份、候选校验与原子提交。
- 模块按冻结 `MigratorDescriptor.id` 映射，编译前拒绝全部 Wasm imports。
- 唯一导出：`memory`（恰好 3 个 64 KiB 页）与 `migrate(i32 input_ptr, i32 input_len, i32 output_ptr, i32 output_capacity) -> i32 output_len`。
- 第 0 页留给 guest 静态数据；第 1 页输入、第 2 页输出由宿主保留。输入/输出各自最多 64 KiB；超过上限显式失败。
- 输入/输出使用确定性 JSON 字节：`MigrationInput` / `MigrationOutput`，字节数组元素为 0..255；对象拒绝未知字段。Schema 为 `schemas/migration-abi-v1.schema.json`。
- 每次调用创建新 Store，memory 上限 192 KiB、Fuel 上限 1,000,000、无宿主导入；同一模块、描述符和规范化输入在两个新 Store 中各运行一次。SHA-256 代码身份、描述符和输入进入确定性监测上下文，观察到输出差异时返回 `platform.mod.determinism_violation`。
- 事务层仍校验输入/输出 Scope；恶意或越权输出会被拒绝，不能直接写 World 或读写宿主文件。
- Wasm guest trap、Fuel 耗尽、ABI 错误均返回 `RunnerFailure`，由 SAVE-007 事务记录并回滚；`ModFaultReport::from_save_migration_error` 保留失败类别和回滚状态。

### 专项验证

- `migration_guest_runs_through_save_runner_and_identical_input_is_monitored`：相同输入由实际 Wasm runner 稳定执行。
- `save_transaction_executes_wasm_migration_and_commits_verified_output`：经实际 `SAVE-007 migrate()` 调用、World/Mod 范围隔离、候选校验、摘要复验及提交。
- `wasm_runner_failure_becomes_rollback_confirmed_platform_diagnostic`：Fuel 用尽后保留可读旧档并生成 Schema 合法平台故障报告。
- `guest_imports_are_rejected_before_execution`：拒绝 WASI 时钟导入。
- `migration_abi_json_matches_the_published_closed_schema`、`malformed_guest_output_fails_closed`：Schema 与失败关闭行为。
