#### 关键发现：全称零半注册保证不成立（已实测复现）

**声明原文**（三处一致）：
- `lib.rs:2323-2325`：「for a batch submitted through `ModRegistry::register_batch`, either every System in the batch is registered and recorded, or none is registered and the record is untouched.」
- `planning/11-P3-05-生命周期执行记录.md:82`：「批次要么全部注册并记录，要么全部不注册且记录不变。」
- `planning/11-P3-05-生命周期执行记录.md:138`：「对单批次的注册零半注册为构造性保证。」

**事实链**：
1. 阶段一校验的是 `declared_id`（调用方传入的字符串），第 4 步用 `validate_type_id(declared_id)`。
2. 阶段二调用 `Kernel::register_system(system)`，而 Kernel 内部（`kernel-core/src/lib.rs:521-531`）**再次**调用 `system.id()` 并对其运行 `validate_type_id`。
3. `System::id()` 是公开 trait 方法（`kernel-core/src/lib.rs:426`），签名 `fn id(&self) -> &str`，**没有幂等性或稳定性约束**。`ModRegistry::register_batch` 的入参为 `Vec<(String, Box<dyn System>)>`，接受任意 `dyn System`。
4. 因此存在一类合法构造的输入：某元素的 `id()` 首次调用返回合法值（通过阶段一），后续调用返回非法值（阶段二失败）。若该元素不是批首元素，则批内**更早的元素已被 `push` 进 Kernel 并已写入 `self.registered`**，随后整批返回 `Err` —— 即**部分提交**。

**复现证据**（独立探针 crate，位于工作区之外 `E:/hexa-verify-scratch/probe-crate`，使用 `CARGO_TARGET_DIR` 隔离，复核结束后已删除）：

```
输入批次：
  [0] ("org.game.first", NamedSystem 其 id() 恒为 "org.game.first")
  [1] ("org.game.shifty", ShiftySystem 其 id() 首次返回 "org.game.shifty"、之后返回 "/illegal")

实测输出：
result = Err(Lifecycle(LifecycleFailure { code: RegistrationRejected,
         mod_id: Some("org.game.shifty"), batch_index: Some(1),
         message: "Kernel rejected Mod ID `org.game.shifty`: invalid system ID `/illegal`" }))
recorded_count = 1
first recorded? true
re-register first => Err(DuplicateSystemId("org.game.first"))
KERNEL_HOLDS_FIRST_AFTER_FAILURE = true
```

即：整批返回失败，但 `org.game.first` **既留在了 Kernel 中、也留在了协调器记录中**，与「全部不注册且记录不变」直接矛盾。

**严重度定级**：
- **不是生产缺陷**：仓库中唯一的 `System` 实现为 `WasmSystem`（`lib.rs:1583-1586`），其 `id()` 返回 `&self.id`（稳定存储的 `String`，见 `lib.rs:1555-1561` 构造），因此生产路径下阶段二不会因 `id()` 变化而失败，该路径**当前不可达**。
- **是 API 契约缺口**：`register_batch` 是公开 API 且接受任意 `dyn System`，其文档以全称量词承诺零半注册；下游任何非幂等 `id()` 的 `System` 均可触发部分提交。文档承诺强于实现能力。
- **报告未披露**：交付报告与执行记录均只陈述该保证成立，未提及 `id()` 非幂等这一边界。

## 3. 已确认的问题与未能证实的保证

### 已确认问题（1 项，非阻塞）

**V-1：`register_batch` 全称零半注册保证过强，与实现能力不符**
- 位置：`crates/platform-core/src/lib.rs:2323-2325`（类型 doc）；`planning/11-P3-05-生命周期执行记录.md:82,138`
- 触发条件：批内非首元素的 `System::id()` 非幂等（阶段一合法、阶段二非法）
- 后果：整批返回 `Err`，但更早元素已提交到 Kernel 并已写入协调器记录（部分提交）
- 现阶段可达性：**生产不可达**（唯一生产实现 `WasmSystem::id()` 稳定）；作为公开 API 契约缺口成立
- 是否阻塞：否

### 未能证实的保证

- 「单批次零半注册」的**全称**形式无法证实（已被反例证伪，仅对幂等 `id()` 输入成立）。
- 「协调器记录始终等于 Kernel 真实注册集合」的**全局**形式无法证实（旁路路径存在，类型 doc 已如实声明，非缺陷）。
