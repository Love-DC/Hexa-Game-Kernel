## 1. 逐项裁决材料

### D-1a — World 域 owner 字面约定

- **待决定的问题：** 世界域（`MigrationDomain::World`）迁移器的「所属 Mod」应填什么值？是存档 Manifest 的 `game_definition.id`，还是保留字面量 `"world"`？
- **提案推荐方案【提案原文】：** 采纳 `game_definition.id`（planning/35 §3.2）。
- **推荐理由【提案原文】：** 世界数据的所有者即游戏定义；§3.4 版本分离语义与 SAVE-005 判定器对 World/Mod Schema 差异均查迁移，故世界域需有明确 owner 归属以便与存档 Manifest 对应。
- **影响【本材料分析】：**
  - 实现：决定 `MigratorDescriptor.owner` 在 World 域的填充值与校验规则（`EmptyOwnerModId` 是否适用于 World 域）。
  - 兼容性：影响描述符数据的来源约定（装配层如何从 Mod 包声明映射 World 域迁移器）。
  - 测试：影响注册表校验用例（空值/非法值）。
  - SAVE-007~012：影响迁移计划的域归属展示与后续装配层转换。
- **不采纳推荐的主要代价【提案原文 + 本材料分析】：** 选 `"world"` 需额外约定保留字面量与 `game_definition.id` 的映射，且与世界数据实际所有者脱钩；代价是概念重复、映射层增多。
- **依赖关系：** 与 D-3d 同属 World 域边界；建议二者一并裁决以保持 World 域约定一致。不阻塞其他项。

### D-2 — 注册唯一性（主键 + 同域同边唯一）与注册期拒绝

- **待决定的问题：** 注册表是否强制 `migrator_id` 全局唯一、且同一 `(domain, from_schema, to_schema)` 仅允许一条边；冲突在注册期拒绝还是查找期择优？
- **提案推荐方案【提案原文】：** 采纳 planning/35 §4.1——主键全局唯一（`DuplicateMigratorId`）+ 同域同边唯一（`ConflictingMigrationEdge`），冲突在**注册期拒绝**。
- **推荐理由【提案原文】：** 边唯一是链查找确定性的结构性前提；同边多迁移器必然歧义，提前到注册期拒绝比查找期择优更直白，且与 §8.3「歧义必须停止」「选择必须确定且可记录」一致。
- **影响【本材料分析】：**
  - 实现：注册表构建函数签名与两个注册期错误变体。
  - 兼容性：决定描述符聚合是否可能因多 Mod 冲突而失败（装配层须处理 `ConflictingMigrationEdge`）。
  - 测试：T-1、T-2。
  - SAVE-007~012：注册期拒绝使查找期歧义来源减少一类，简化执行与诊断。
- **不采纳推荐的主要代价【提案原文】：** 备选「查找期择优」把确定性寄托于排序规则，且与 §8.3 歧义停止语义冲突；代价是判定结果可能随实现或顺序漂移。代价二：同边并行迁移实现无法共存，须 Mod 作者合并为单迁移器。
- **依赖关系：** **先决项**。D-3a（多路径策略）、D-3b（循环落实）以「边已唯一」为前提；D-3f（歧义诊断）以存在唯一歧义来源为前提。

### D-3a — 多路径策略（歧义拒绝）

- **待决定的问题：** 当同一查询存在 ≥2 条有效迁移路径时，是拒绝（歧义）还是按某规则择优？
- **提案推荐方案【提案原文】：** **歧义拒绝**（planning/35 §5.3）——发现 ≥2 条有效路径即 `AmbiguousMigrationPath`。
- **推荐理由【提案原文】：** §8.3 明示「歧义必须停止」，且规范未规定任何择优规则（最短/最新/注册序均无依据）；规范沉默处自行择优等于发明规则。
- **影响【本材料分析】：**
  - 实现：查找核心判定分支（阈值 2）。
  - 兼容性：合法的多实现并存场景被拒绝，须注册方消解。
  - 测试：T-10、T-19、T-22。
  - SAVE-007~012：歧义在规划阶段即阻断，执行层不会遇到多路径选择。
- **不采纳推荐的主要代价【本材料分析】：** 若择优，需凭空定义排序规则并写入契约，且违背 §8.3 字面；风险是同一存档在不同环境/版本下可能选中不同路径，破坏 §5.2「判定可重复」。
- **依赖关系：** 依赖 D-2；是 D-3b、D-3c、D-3f 的**语义父项**（它们都以「≥2 条 ⇒ 拒绝」为前提）。

### D-3b — 循环落实（不设独立 CycleDetected）

- **待决定的问题：** §8.3 要求「迁移链存在循环必须停止」，但 §8.2 允许显式逆向迁移器（含环图合法）。二者如何调和？
- **提案推荐方案【提案原文】：** planning/35 §5.3——①选中链为简单路径、构造性无环；②环导致的 ≥2 条简单路径按歧义拒绝；③环不构成多路径则不阻断；**不设独立 `CycleDetected` 错误**；注册期不拒环。
- **推荐理由【提案原文】：** §8.2 显式逆向迁移器合法，故含环图本身不得在注册期拒绝；「循环必须停止」由「简单路径 + 多路径归歧义」落实，避免与 §8.2 冲突。
- **影响【本材料分析】：**
  - 实现：DFS 使用节点不重复（简单路径）约束；无环专用错误变体。
  - 兼容性：显式逆向迁移器（`1→2`+`2→1`）可注册成功（T-4）。
  - 测试：T-4、T-10（含显式环导致的多路径）。
  - SAVE-007~012：执行层不会收到「循环」类错误，只收到歧义/缺失/不兼容。
- **不采纳推荐的主要代价【本材料分析】：** 若注册期一律拒绝含环图，则显式逆向迁移器无法注册，直接违反 §8.2；若设独立 `CycleDetected`，需额外定义与歧义的优先级关系，增加语义面。
- **依赖关系：** 依赖 D-3a（②的前提是歧义拒绝策略）。

### D-3c — `requires` 不满足的路径处理

- **待决定的问题：** 候选路径的 `requires` 依赖在环境集合内无满足者时，归为「不兼容步骤」还是「无路径」？
- **提案推荐方案【提案原文】：** planning/35 §5.2/§6——排除该路径；若最终 0 条有效路径且存在不兼容候选，优先报 `IncompatibleStep`（诊断优于裸缺失）。
- **推荐理由【提案原文】：** 区分「根本没有候选」与「有候选但依赖不满足」可为诊断提供更精确信息；§8.3 要求「不兼容步骤必须停止」，`IncompatibleStep` 正是其机器表达。
- **影响【本材料分析】：**
  - 实现：查找期需追踪「是否存在不兼容候选」标志；`IncompatibleStep` 携带 `unsatisfied: Vec<(migrator_id, 依赖)>`。
  - 兼容性：影响 D-4b 的映射（该错误同样归 `Unavailable`）。
  - 测试：T-11、T-20。
  - SAVE-007~012：诊断层可获得缺失依赖明细（装配层保留）。
- **不采纳推荐的主要代价【本材料分析】：** 一律报 `NoMigrationPath` 会丢失「依赖不满足」这一可操作诊断，用户无法得知应安装哪个依赖；代价是可诊断性下降。
- **依赖关系：** 与 D-3a、D-6 交互（错误码归属）。

### D-3d — World 域目标版本来源

- **待决定的问题：** 链查找的终点（当前 World Schema 版本）从何而来？工作区当前无权威来源。
- **提案推荐方案【提案原文】：** planning/35 §5.1——由**装配层显式注入**；本包不读 crate 常量或环境；该注入要求写入契约并标注候选 GAP-27 未关闭。
- **推荐理由【提案原文】：** `planning/28` §2.4 已证 `world_schema_version` 与 kernel-core 私有 `SNAPSHOT_FORMAT_VERSION` 语义不同、无映射、不得互推；`planning/32` 候选 GAP-27 已登记「无权威世界 Schema 版本来源」。
- **影响【本材料分析】：**
  - 实现：World 域查找需新增注入参数；无法自行推导终点。
  - 兼容性：依赖尚未存在的权威来源（GAP-27）；当前只能由调用方提供。
  - 测试：需测试专用注入值。
  - SAVE-007~012：GAP-27 未解决前，World 域迁移在生产装配层可能无法真实运转。
- **不采纳推荐的主要代价【本材料分析】：** 若强行从 crate 版本或 kernel-core 常量推导，违反 `planning/28` §2.4「不得互推」，属事实错误。
- **依赖关系：** 与 D-1a 同属 World 域；**【待补证据】** 见 §4。

### D-3e — `input_scope` 声明涉及他 Mod 数据是否施加额外注册约束

- **待决定的问题：** 迁移器描述符声明 `input_scope` 涉及其他 Mod 数据范围时，SAVE-006 是否应施加额外注册约束（如要求显式审批标记）？
- **提案推荐方案【提案原文】：** planning/35 §3.4——**不施加，仅承载**；`input_scope` 声明本身不违反 §8.4（§8.4 禁止的是**执行时**访问他 Mod 私有存储），注册期不拒绝，但作为诊断信息保留。
- **推荐理由【提案原文】：** 区分「规范禁止的行为（执行期）」「受控接口读取（当前不存在）」「描述符声明（元数据）」三层，避免把声明误当作行为。
- **影响【本材料分析】：**
  - 实现：注册期校验不含「他 Mod 数据范围」拒绝分支；描述符保留该字段用于计划与诊断。
  - 兼容性：不引入额外审批流程。
  - 测试：无需拒绝用例；T-18 等不受影响。
  - SAVE-007~012：执行期是否真的违规留给 SAVE-007/GAP-24(c) 与执行环境。
- **不采纳推荐的主要代价【本材料分析】：** 若注册期拒绝此类声明，会与 §8.4 的实际约束层面错位（把执行期约束施加到注册期），且无规范依据。
- **依赖关系：** 独立；与 D-5a（GAP-24 范围）相关（执行期约束归 (c)）。

### D-3f — 歧义诊断字段与 `truncated` 语义

- **待决定的问题：** `AmbiguousMigrationPath` 的诊断字段应保留到什么程度？是否设「全部候选总数」？
- **提案推荐方案【提案原文】：** planning/35 §5.2/§9.1——保留 `discovered_chains`（≤3 条，按 hop 序列字典序）+ `truncated: bool`（`true`=触达收集上限、完整性未知；`false`=已穷尽、所列即全部）；**不设 `total_candidates`**。
- **推荐理由【提案原文】：** 有界收集（`DISCOVERY_LIMIT = 3`）下无法准确计算总数，已发现数量不得冒充总数；`truncated` 只表达「完整性是否已知」，不表达「已证明存在第 4 条」。
- **影响【本材料分析】：**
  - 实现：错误变体字段与序列化；`truncated` 的计算点。
  - 兼容性：不触及 SAVE-005 冻结面（诊断留在装配层）。
  - 测试：T-10、T-19（三分场景）、T-22。
  - SAVE-007~012：诊断层可据 `truncated` 决定是否提示「可能存在更多路径」。
- **不采纳推荐的主要代价【提案原文】：** 保留全部候选 → 指数风险；保留 `total_candidates` → 有界收集下数值不实（**禁止冒充总数**）。
- **依赖关系：** 依赖 D-3a（须先采纳歧义拒绝）与 D-3g（若引入预算，`truncated` 语义需扩展）。

### D-3g — 搜索复杂度风险是否接受

- **待决定的问题：** 唯一路径/无路径的证明需穷尽搜索，病态大图最坏指数级；是否引入搜索预算或复杂度限制？
- **提案推荐方案【提案原文】：** planning/35 §5.3——**接受风险、暂不引入预算**。理由：实际迁移图预期近线性；预算引入「预算耗尽」新失败模式且不得报为无路径（须新增独立稳定码）；无性能证据。
- **推荐理由【提案原文】：** 同上三条。
- **影响【本材料分析】：**
  - 实现：不新增预算参数与错误变体。
  - 兼容性：无。
  - 测试：T-19/T-21/T-22 覆盖有界收集与穷尽一致性；无预算测试。
  - SAVE-007~012：若后续出现病态图，须补预算设计。
- **不采纳推荐的主要代价【本材料分析】：** 引入预算 → 须同步批准独立稳定码 `save.migration.search_budget_exceeded` 及语义（预算耗尽 ≠ 无路径 ≠ 歧义），并新增测试；代价是契约面与实现面扩大。
- **依赖关系：** 与 D-3f 交互（若引预算，`truncated`/诊断字段需重新定义）；与 D-6 交互（新稳定码）。**风险未解决**，见 §3。

### D-4a — 迁移计划归属 SAVE-006

- **待决定的问题：** §8.5 步 7「生成迁移计划」归 SAVE-006 还是 SAVE-007？
- **提案推荐方案【提案原文】：** planning/35 §7.1——**归 SAVE-006**（构建与链验证），执行面归 SAVE-007。
- **推荐理由【提案原文】：** §8.5 步 1-3 已由 SAVE-005/006 覆盖；步 7 是纯数据产物，与链查找共享同一图与输入；三段（判定/计划/执行）各自可测试可冻结。
- **影响【本材料分析】：**
  - 实现：新增 `MigrationPlan`/`PlannedMigration` 类型与计划构建函数。
  - 兼容性：不触碰 SAVE-005 冻结面。
  - 测试：T-15、T-16。
  - SAVE-007~012：SAVE-007 消费不可变计划执行；SAVE-008 备份/回退基于计划。
- **不采纳推荐的主要代价【本材料分析】：** 若归 SAVE-007，计划构建与链验证分散至两包，SAVE-006 仅做查找，「计划生成」测试要求（§15.1）落点模糊。
- **依赖关系：** 是 D-4c 的前提；与 D-4b 独立。

### D-4b — 查找失败 → SAVE-005 判定器映射（接受信息损失）

- **待决定的问题：** `NoMigrationPath`/`AmbiguousMigrationPath`/`IncompatibleStep` 统一映射为 `MigrationPath::Unavailable` 后，SAVE-005 只能报 `schema_mismatch_no_migration`；是否接受这一机器可读信息损失？
- **提案推荐方案【提案原文】：** planning/35 §7.4 **方案①**——统一映射为 `Unavailable`，接受信息损失，详细 `MigrationLookupError` 由装配层保留给诊断层（SAVE-011）；SAVE-005 冻结面零改动。
- **推荐理由【提案原文】：** SAVE-005 的 11 原因码已冻结、无更精确码；唯一替代是修订 SAVE-005 新增原因码，代价是重新验收 SAVE-005。
- **影响【本材料分析】：**
  - 实现：装配层映射函数（不属 save-manager 内本包实现范围）。

## 3. 任务书点名五项展开核对

### 3.1 D-3f — 有限歧义诊断字段与 `truncated` 语义

- 字段：`discovered_chains: Vec<Vec<String>>`（≤3 条，hop 的 `migrator_id` 序列，按字典序）+ `truncated: bool`；**无 `total_candidates`**。
- `truncated` 定义：`true` = 因触达 3 条收集上限而停止、**完整性未知**（不代表已证明存在第 4 条）；`false` = 搜索穷尽，`discovered_chains` 即**全部**有效路径。
- 覆盖测试：T-10、T-19（(a) 恰好 2 条穷尽 ⇒ false；(b) 恰好第 3 条触发上限 ⇒ true；(c) ≥4 条 ⇒ true）、T-22。
- 与 D-3g 的接口：若引入预算，须定义「预算耗尽」是否也置 `truncated`，或新增独立标记。

### 3.2 D-3g — 搜索复杂度风险

- 现状：歧义判定可提前确定；唯一路径/无路径证明须穷尽搜索，病态大图最坏指数级；`requires` 剪枝不改变有效路径集合，也不改变最坏情况。
- 提案：接受风险、不引预算（近线性预期 / 避免新失败模式 / 无性能证据）。
- **状态：风险未解决**（提案原文标注）。负责人须明确：接受该未解决风险，或要求引入预算（将连带 D-6 新增稳定码、D-3f 扩展语义）。

### 3.3 D-4b — SAVE-005 统一失败映射的信息损失

- 损失点：`AmbiguousMigrationPath`（有路径但歧义）与 `IncompatibleStep`（有路径但依赖不满足）在 SAVE-005 机器可读层面统一为 `schema_mismatch_no_migration`——**不精确**（非「无迁移」，而是「无可用迁移」）。
- 提案：接受损失；详细 `MigrationLookupError` 由装配层保留给 SAVE-011；**不修改已冻结的 `MigrationPath`/`MigrationHop`**。
- 替代：修订 SAVE-005 新增原因码 → 重新验收 SAVE-005（提案标注不推荐）。

### 3.4 D-5b — GAP-25 故障报告交接路径

- 路径：save-manager 结构化错误 →**装配层适配器** → `ModFaultReport::new("platform.mod.migration_failed", …)`；既有映射 L4Runtime / Rebuild / RestoreCheckpoint。
- 缺口：适配器**当前不存在**；save-manager 不依赖 platform-core（R-13）；本包只冻结错误语义/码/字段。
- 归属：适配器实现归 SAVE-007 或独立装配层任务；SAVE-012 验收。

### 3.5 D-6 — 稳定码与诊断字段范围

- 码表：`save.migration.duplicate_migrator_id` / `conflicting_edge` / `invalid_descriptor` / `no_path` / `incompatible_step` / `ambiguous_path`（后三者与 §6 表一致）。
- 变体字段：注册期 `DuplicateMigratorId{id}`、`ConflictingMigrationEdge{domain,from,to,existing_id,new_id}`、`InvalidDescriptor{id:Option,field,reason}`；查找期 `NoMigrationPath{domain,from,to}`、`AmbiguousMigrationPath{domain,from,to,discovered_chains,truncated}`、`IncompatibleStep{domain,from,to,unsatisfied}`。
- 字段裁剪：5 判定谓词（id、owner/domain、from_schema、to_schema、requires）+ 其余「仅承载」；`resource_budget: BTreeMap<String,u64>`、`verification: {RoundTrip/GoldenDigest/Custom}`、`MigrationDataScope{world:bool,mods:BTreeSet<String>}`。
- 与 SAVE-005 例码 `SAVE_MOD_REQUIRED_MISSING` 的关系：Save 规范 §13 仅示例、不约束命名（`planning/33` 已确认先例）。
