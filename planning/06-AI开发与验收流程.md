# AI 开发与验收流程

- 适用范围：Game Kernel 的文档、代码、工具和测试
- 当前状态：流程设计；尚无 Git、`AGENTS.md`、CI 或构建工具

## 1. 建议的仓库骨架


这是候选目录，不是现有目录。模块可按语言调整；依赖方向不得因此变化。避免在没有实现需求前创建空模块。

## 2. AGENTS.md 规则

根 `AGENTS.md` 应说明项目目标、术语和权威规范链接、模块边界、构建/测试命令、状态标签、任务卡及交付报告要求。子目录规则只补充局部约束，不重复维护全局契约。

每个 AI 任务开始前：

1. 读取根规则和任务涉及模块的局部规则。
2. 读取对应规范/任务卡与当前实现，不凭聊天记忆假设接口。
3. 报告目标、修改边界、依赖和计划验证方式。
4. 对规范缺口先开问题项或提出方案，不用实现绕过契约。

## 3. 任务卡与执行顺序

每张卡必须包含：ID、目标、模块、前置依赖、可改目录、遵循规范、实施要求、测试要求、验收标准、交付报告。按依赖图选取可并行任务；涉及同一公共接口或共享文件的任务先由一个任务冻结契约，再分发实现。

执行循环：

```text
读取基线 → 确认任务边界 → 小步实现 → 增加/更新针对性测试
    → 运行要求的检查 → 检查差异与文档 → 提交证据和剩余风险
```

发现规范与实现冲突时，暂停受影响的变更，说明冲突、范围、备选修复和推荐方案；不要悄悄重写冻结接口。

## 4. Git 与变更管理

- P1 获批后建立 Git 仓库和默认分支保护规则；每项工作保持小而可审查的提交。
- 分支或工作区按任务隔离；公共类型、格式和契约变更先单独提交。
- 不把生成物、密钥、玩家个人存档或测试中非公开数据提交进仓库。
- 不执行破坏性重写或批量删除；变更范围需能映射到任务卡。
- 每次交付提供变更摘要、文件清单、验证命令与结果、未做事项。

## 5. 质量门禁

### 变更前

- 任务有验收条件与负责人（模块/AI/复核角色）。
- 输入规范和现状代码已经检查。
- 公共 API、序列化或权限变化有兼容/迁移方案。

### 本地与 CI

由工具链锁定后固定命令入口，至少覆盖：格式、静态检查/编译、单元测试、Kernel 契约测试、Platform Schema/依赖测试、确定性重复运行、快照恢复、故障注入及必要的安全测试。后续按阶段加入重放、多人同步、长时间运行和性能回归。

CI 必须从干净检出运行，不依赖开发者机器上的未记录文件。每个失败都应输出稳定错误和可定位模块。CI 通过是交付证据之一，不替代存档恢复或用户体验验收。

### 当前本轮

本轮只有规划文档交付，没有源码/测试项目，所以没有执行构建、测试或 CI。将来执行任务卡时，必须实际运行对应命令；没有运行的检查标为“未执行”，不能写成通过。

## 6. 规范/实现状态管理

| 状态 | 含义 | 允许如何报告 |
|---|---|---|
| 已确认 | 项目负责人确认的目标或产品约束 | 可作为后续任务的稳定输入；变更需记录批准。 |
| 待设计 | 尚无具体方案 | 只能报告问题和方案，不可说已实现。 |
| 待验证 | 有方案但未通过实现/实验验证 | 必须明确验证缺口。 |
| 已实现 | 代码或文档已存在 | 不等于测试通过或验收。 |
| 已验收 | 所规定的检查已实际通过并有证据 | 报告对应命令、日志/结果、环境和范围。 |
| 已废弃 | 被正式替代或删除 | 记录原因、替代项及迁移方式。 |

文档中“冻结”必须注明冻结对象（边界、行为、类型还是具体 API）。设计草案的原则不得被提升为已验收功能。

## 7. 验收与完成报告

任务完成报告模板：

```text
任务 ID / 状态：
实现内容：
变更文件：
遵循的规范与决策记录：
执行的命令及结果：
未执行的检查及原因：
验收标准逐项结果：
剩余风险 / 后续依赖：
```

完成定义：需求与实现一致；自动检查真实运行；错误/恢复路径有测试；文档/Schema/API 同步；没有占位功能冒充完成；未解决问题和下一步明确。代码行数、文档数量和 AI 自我判断不能代替验收。

## 8. 多代理与复核

只有在任务可独立、公共契约已冻结且改动范围不重叠时，才把任务交给不同 AI。一个集成负责人负责依赖排序、合并冲突和最终验收。另一个代理的完成报告是待复核信息，不能替代本仓库的实际测试结果。

代码审查优先检查：状态所有权绕过、非确定性来源、错误被静默吞掉、迁移覆盖原档、权限自我授权、数据/Schema 版本不一致、未经声明的依赖和没有执行证据的完成声明。

## 9. 当前下一步

项目负责人确认 D-01 后，执行 P1-01 建立 Git/工具链/AI 规则/CI，然后按《第一阶段详细任务卡》依赖顺序工作。P1 结束后由 AI 出示完整验证证据；负责人通过可运行的 headless 演示和报告进行范围验收，再决定是否进入 P2。
