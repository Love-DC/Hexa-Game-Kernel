# 第一阶段详细任务卡：最小垂直切片

- 阶段：P1
- 状态：范围已获负责人批准；P1 实施与验收完成，见 `planning/07-P1实施与验收报告.md`
- 总目标：构建并运行一个最小世界；执行一个受控 Mod 的逻辑；验证状态变化、保存/恢复、确定性摘要与自动检查。
- 阶段外：完整 UI、联机、商店、热加载、任意原生 Mod、复杂玩法和未经测量的 300+ 容量承诺。
- 共同约束：所有任务遵守 `Project Architecture` 依赖边界、Kernel/Mod/Save 现存草案；不得静默忽略错误，不得伪称未执行的测试通过。

## GK-P1-01 — 建立工程基线

- **目标/模块：** 工程治理、构建与 CI。
- **依赖：** P1 获批。
- **可改范围：** 仓库根目录、工具链/构建配置、`AGENTS.md`、CI 配置、`scripts/`、最小测试骨架。
- **实施：** 初始化或确认 Git；记录语言和锁定工具链；定义从干净检出到构建/测试的单一命令；加入格式、静态检查和 CI；生成根级 AI 规则。Rust 是当前文档的工作候选，若验证后不采用，先记录原因和新基线。
- **测试：** 在干净工作副本运行环境检查、构建、格式、静态检查、最小测试和 CI 同等命令。
- **验收：** 新环境可按 README 复现；工具版本被锁定；规则与 CI 一致；构建失败可定位。
- **交付报告：** 工具版本、命令、真实结果、平台限制、变更路径。

## GK-P1-02 — 冻结 MVP Kernel API 类型

- **目标/模块：** Kernel API 契约。
- **依赖：** P1-01。
- **可改范围：** `crates/kernel-api/**`（或经记录批准的等价模块）、契约文档、API 测试。
- **实施：** 定义 Tick、EntityId、WorldId、Component/Resource ID、CommandId、CommandEnvelope、EventRecord、StateHash、稳定错误类型；明确可见性、ID 唯一范围、Schema 版本与序列化边界。只实现 MVP 必需类型，不一次性冻结完整 SDK。
- **测试：** 类型边界、编码/解码往返、非法值拒绝、稳定错误码契约。
- **验收：** 只有一个权威类型定义；Platform/运行时不得复制出语义不同的类型；接口与文档同步。
- **报告：** 新增/修改类型、兼容性影响、测试证据和未定字段。

## GK-P1-03 — 实现逻辑 Tick 与串行调度

- **目标/模块：** Time、Scheduler、System Registry。
- **依赖：** P1-01、P1-02。
- **可改范围：** `crates/kernel-core/src/time/**`、`scheduler/**`、`system/**` 及单元测试。
- **实施：** Tick 初始为 0；成功 step 恰好推进 1；错误不回绕；按阶段和稳定 SystemId 建立确定计划；第一版串行执行，不做并行优化。
- **测试：** Tick 边界/溢出、稳定排序、缺依赖、循环依赖、重复运行计划一致性。
- **验收：** 不读系统时钟决定模拟；注册/文件顺序不会改变计划；无效图在执行前拒绝。
- **报告：** 调度规则、错误分类、测试命令与结果。

## GK-P1-04 — 建立最小权威 World

- **目标/模块：** World、实体分配器、最小组件/Resource 存储。
- **依赖：** P1-02。
- **可改范围：** `crates/kernel-core/src/world/**`、规范化查询测试。
- **实施：** 只做验证垂直切片所需的最小数据模型；Entity ID 稳定且销毁后失效；查询结果具有稳定顺序；权威值具备明确类型/Schema 标识。
- **测试：** 实体创建/销毁、旧 ID、跨 World ID、稳定遍历、无效组件/资源拒绝。
- **验收：** 外部调用无可变 World 容器引用；状态修改只由提交接口执行；权威状态集合可被完整枚举/规范化。
- **报告：** 状态所有权、查询顺序和未纳入快照的数据清单。

## GK-P1-05 — 实现 Command 验证与原子提交

- **目标/模块：** Command Pipeline、错误码。
- **依赖：** P1-02、P1-04。
- **可改范围：** `crates/kernel-core/src/command/**`、事务/故障测试。
- **实施：** 验证来源、目标 Tick、序号、权限钩子、Entity 和 Schema；定义 MVP 的稳定排序键；单条复合命令全成或全撤销；普通拒绝不改变其目标状态；确定 Tick 事务的 staging/commit 可见边界。
- **测试：** 拒绝原因、重复 ID、先 Spawn 后 Set、单条命令中途失败、各提交阶段故障注入与状态对照。
- **验收：** 所有 World 写入均可追踪；命令拒绝不静默；不可恢复核心错误时不暴露半个 Tick；该保证有自动测试证据。
- **报告：** 提交顺序算法、回滚边界、注入故障列表和结果。

## GK-P1-06 — 执行最小 System 并提交输出

- **目标/模块：** System 执行器和 Command 集成。
- **依赖：** P1-03、P1-04、P1-05。
- **可改范围：** `crates/kernel-core/src/system/**`、集成测试。
- **实施：** System 只能读取获准快照/视图并产生待处理命令；所有系统命令按执行计划和 System 内序号排序后统一验证；实现一个简单状态递增/资源更新 System 作为纵向样例。
- **测试：** System 不可直接写 World 的 API 边界、相同输入输出相同命令、系统失败时输出全部撤销、非法计划拒绝。
- **验收：** 不依赖线程完成时间；无效命令不会部分应用；必需 System 失败策略可观察且与 GAP-08 决策一致。
- **报告：** 示例 System 行为、调度计划、错误和预算处理。

## GK-P1-07 — 实现 Tick Event 与诊断输出

- **目标/模块：** Event、错误诊断。
- **依赖：** P1-05、P1-06。
- **可改范围：** `crates/kernel-core/src/event/**`、错误类型、集成测试。
- **实施：** 命令提交成功后才产生对应事实事件；本 Tick 事件在封存点统一输出；暂不实现递归订阅/回调写 World；拒绝事件包含来源和稳定原因。
- **测试：** 提交成功/失败事件、Event 顺序、阶段边界、过限/非法负载、事件消费者不能绕过 Command。
- **验收：** 输出不能宣称未发生的事实；顺序可重放；事件类型和保留范围有文档。
- **报告：** 当前支持的事件种类、排序规则和暂缓能力。

## GK-P1-08 — 规范化状态摘要与快照恢复

- **目标/模块：** StateHash、Kernel 快照接口。
- **依赖：** P1-04、P1-05、P1-07。
- **可改范围：** `crates/kernel-core/src/snapshot/**`、序列化与哈希模块、恢复测试。
- **实施：** 固定 MVP 序列化和哈希格式标识；覆盖 Tick、实体分配器、全部权威实体/组件/Resource 和影响后续结果的随机状态；恢复后验证 Schema 与完整性。
- **测试：** 同输入重复哈希相同；保存/恢复后继续 N Tick 与不中断运行一致；损坏/未知版本拒绝且原始字节不改。
- **验收：** 排除地址、时戳、容器容量和表现状态；恢复结果可复现；未覆盖状态明示。
- **报告：** 格式版本、哈希算法、输入字段、恢复和故障测试证据。

## GK-P1-09 — 建立 MVP Manifest 与确定性加载计划

- **目标/模块：** Mod Validator、Resolver、最小锁文件。
- **依赖：** P1-01、P1-02。
- **可改范围：** `platform/mod-manifest/**`、`platform/mod-resolver/**`、Schema/夹具/测试。
- **实施：** 为 P1 实际使用字段定义机器可校验 Schema；检查 ID、版本、入口、Kernel API、运行时、依赖和权限请求；生成锁定版本与内容摘要；检测缺失/循环依赖。不实现商店下载。
- **测试：** 合法/非法样例、未知字段策略、缺依赖、循环、内容摘要不匹配、相同输入计划一致。
- **验收：** 错误定位到字段；Launcher 提交不能绕过 Platform 校验；锁文件中实际包和解析顺序可复现。
- **报告：** Schema 版本、支持字段/限制及测试命令和结果。

## GK-P1-10 — 验证受控脚本运行时

- **目标/模块：** Mod Runtime、Host API、安全预算。
- **依赖：** P1-01、P1-02、P1-05、P1-09。
- **可改范围：** `platform/mod-runtime/**`、`platform/permissions/**`、运行时 ADR、隔离测试。
- **实施：** 对受支持 Wasm 运行时做技术验证并锁定实际引擎/版本；仅开放 MVP 所需的 World 只读、Command 输出和受控随机数 Host API；拒绝未授权资源访问；明确燃料/内存限制和版本参与锁定配置。普通 Mod 不运行进程内原生代码。
- **测试：** 有效模块、非法 ABI、越权 Host 调用、预算耗尽、异常中断、未提交命令撤销、重复执行确定性。
- **验收：** Manifest 申请不自动授权；脚本不能访问任意文件/网络/进程；运行时版本/配置进入锁文件；失败有可定位诊断。
- **报告：** 候选比较、选定版本/理由、隔离边界、已知限制和测试证据。

## GK-P1-11 — 制作一个端到端测试 Mod

- **目标/模块：** 示例 Mod、Mod→Kernel 集成。
- **依赖：** P1-03 至 P1-10。
- **可改范围：** `examples/mods/p1-counter/**`、测试夹具、最小教程。
- **实施：** Mod 被发现、校验、依赖解析、授权、加载和执行；在指定 Tick 生成 Command，成功后产生 Event；能够保存/恢复；记录其精确摘要和运行时。
- **测试：** 成功路径；Manifest/ABI 错误；权限拒绝；命令被拒绝；预算超限；恢复后重放。
- **验收：** 样例真实经过同一运行时/Host API，不用进程内测试替身冒充脚本；新开发者按教程可复现。
- **报告：** 从空配置到运行/恢复的命令、预期输出和真实结果。

## GK-P1-12 — P1 集成门禁与交付审查

- **目标/模块：** 系统集成、自动化质量门禁、阶段验收。
- **依赖：** P1-01 至 P1-11。
- **可改范围：** 集成测试、CI、`docs/`、任务报告。
- **实施：** 将任务书 MVP 十项逐项映射到自动测试/可检查证据；执行干净构建、单测、契约、集成、确定性、存档恢复和故障注入；记录性能基线但不承诺目标容量。
- **测试：** 通过 P1 定义的全部流水线；若平台暂不支持某项，记录 blocker，不得标绿。
- **验收：** 代码、文档、测试同版本；所有成功声明有命令输出；P1 未实现项和进入 P2 前置条件清楚列出。
- **报告：** 按《AI 开发与验收流程》的完成报告模板逐条给证据。

P1 只有在 P1-12 通过后才算完成。任务卡已写出不代表任务已完成；任何未执行的测试都必须标为“未执行”。
