# P4-SAVE-008 备份、恢复与故障注入实施契约

- **文档编号：** planning/41
- **状态：** 按负责人“继续直至 P4 结束”的委托，采用保守默认值的实施契约
- **依据：** Save §10、§15.2–§15.4；`planning/22`；SAVE-004 `planning/30`；SAVE-007 `planning/39` 与 `planning/40`

## 1. 范围

为现有 `save-manager` 增加显式备份创建、验证、恢复与保留策略，以及可重复故障注入合同测试。迁移前恢复点继续由 SAVE-007 持有，SAVE-008 不改变其事务日志协议。普通保存、迁移、兼容性与 Kernel/Platform 语义保持原边界。

## 2. 保守默认策略

- 手动备份及迁移前备份必须保留；禁止策略清理。
- 成功保存后的历史版本保留为可选策略，默认关闭。
- 只有被明确标记为“保存后历史版本”的备份可以按数量/字节配额裁剪。
- 保留策略若无法确认至少一个当前有效存档或恢复点仍存在，必须拒绝裁剪。
- 备份为源档完整字节的不可变副本，附 sidecar 元数据（源 save ID/root、格式版本、创建时间由调用者传入、用途、可选迁移计划摘要/目标 schema）。所有 sidecar 路径由 API 根据目标和校验过的 ID 推导，不能接受外部任意路径。
- 创建备份先 `create_new` 写同目录临时对象、`sync_all`、读回并 `inspect_save`，校验 save ID/root 后才发布为备份；不承诺断电耐久性。
- 恢复必须先检查备份，再写同目录恢复临时文件、读回检查，最后替换目标并重新检查目标；失败保留源备份和当前目标，不将失败伪装为成功。
- 不使用 glob；只操作清单明确列出的确切路径。未知文件不删。

## 3. 故障注入接口

故障点通过仅测试可见的阶段注入器表达，不新增生产环境全局开关，也不依赖真实磁盘耗尽。至少覆盖 Save §15.3 的 11 类场景：磁盘空间不足、写入失败、文件截断、摘要不匹配、提交前中断、提交后中断、迁移器崩溃、Mod 数据损坏、依赖 Mod 缺失、迁移链不完整、恢复备份损坏。对与 SAVE-008 无关的兼容/迁移场景，测试调用既有 SAVE-005/006/007 接口并断言错误边界；不虚构已存在平台迁移 ABI。

每个故障用例均须断言：错误分类稳定、目标旧档或新档处于一个已验证状态、原始恢复点字节未被破坏、恢复动作可重复且不会重跑迁移器。恢复备份损坏必须保留损坏证据并拒绝覆盖目标。

## 4. I/O 与文件边界

新增唯一生产 I/O 模块 `crates/save-manager/src/backup.rs`；DC-10 源码约束允许列表扩展为 writer、loader、transaction、backup 四个具名模块。其它 save-manager 生产模块仍禁止文件、网络、进程、系统时钟访问。时间戳由调用方注入。不得修改 `kernel-core`、`platform-core`、Cargo 依赖或既有格式/golden vector。

## 5. 最小 API 形状

- `BackupPurpose`：MigrationPreflight / Manual / SuccessfulSaveHistory。
- `BackupMetadata`：备份 ID、源 save ID/root、格式版本、调用方提供的时间戳、用途、可选 plan digest/目标 schema。
- `BackupPolicy`：成功保存历史备份数量/字节上限；手动与迁移备份不可由策略裁剪。
- `create_backup`、`inspect_backup`、`restore_backup`、`prune_history`：均返回稳定结构化错误与明确结果；恢复前后完整性检查必须可观察。

具体类型可在不改变上述可见行为的前提下按现有模块命名习惯调整。

## 6. 验收门槛

- 创建/读取/恢复备份成功；元数据与所含存档身份/摘要对应。
- 损坏备份拒绝恢复；当前目标和备份文件保持不变。
- 恢复写入失败、目标切换失败时不丢失源备份；报告稳定失败阶段。
- 配额裁剪只删除明确枚举的历史备份，且永不删除手动/迁移前备份或最后有效恢复点。
- Save §15.3 的故障矩阵逐例通过；每例有原档可恢复断言。测试需区分“模拟故障合同已覆盖”和“真实 OS 磁盘耗尽/进程强杀尚未跨平台验证”。
- `cargo fmt --all -- --check`、`cargo clippy --workspace --all-targets -- -D warnings`、`cargo test --workspace` 与 `cargo run -p game-platform -- demo` 在最终收尾时实际运行；此契约本身不表示命令已运行。
