## 一、P4 目标与范围

**目标（roadmap P4）：** 长期保存、迁移与分歧定位。交付：存档格式、快照恢复、迁移事务、迁移日志、黄金存档与输入重放。

**范围内：**
1. 存档格式与必需元数据；格式版本与数据版本分离。
2. 世界与 Mod 数据分区、数据所有权与隔离。
3. 兼容性判定模型（四类结论 + 机器可读原因码）。
4. 迁移器合同、迁移链、迁移前验证、迁移事务与原子提交。
5. 备份与恢复；故障注入验证。
6. 正常保存/加载的一致快照边界。
7. 损坏与未知版本保护、诊断。
8. 自动化测试、故障注入与历史存档回归（黄金档 + 输入重放差异定位）。
9. **GAP-24（`DeterminismViolation` 检测）、GAP-25（`MigrationError` 检测）随本阶段落地**（C-2）。

**不在范围（本阶段明确不做，见 §八）：** 联机（P5）、SDK/Launcher（P6）、安全/性能规范与 300+ 基准（P7）、原生模块、热加载、Kernel 语义变更。

  1. Save Manifest JSON Schema 发布且与 Rust 模型一致。

## 七、与 Mod 版本变化 / 旧存档兼容的边界条件

- **版本分离：** Mod 版本变化 ≠ 数据结构变化；迁移必须以 **Schema 版本**为依据（§3.4）。
- **新增 Mod：** 能否加入旧存档由 Compatibility Resolver 判定（§6），**不得自动绕过**兼容性检查（§15.4）。
- **更新 / 移除 / 替换 Mod：** 须有明确转换合同，否则阻止（§7）；移除拥有持久化数据的 Mod 不得静默丢弃数据。
- **跨 Mod 引用失效：** 必须可检测，**不得自动改指**（§4.3）。
- **未知未来格式：** 高于支持版本的存档**禁止普通写入**（§12.2）。
- **降级：** 不自动推断逆向迁移；需已验证逆向迁移或从备份恢复（§8.2）。
- **与确定性/重放：** 迁移必须确定性（§8.4）；**GAP-24 检测落地前，不得声称运行期可判定确定性违规。**
- **重放边界（F-8，GK-P4-00-FIX-03）：** P4 的"重放"仅指**同一确定性边界内的回归重放**（黄金存档 + 输入重放以定位差异）；**跨版本/跨平台重放属独立能力，不在 P4 范围**（`Kernel Contract v1.0.md` §10/§14；存档兼容不蕴含重放兼容）。
