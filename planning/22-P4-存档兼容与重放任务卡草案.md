## 一、P4 目标与范围

**目标（roadmap P4）：** 长期保存、迁移与分歧定位。交付：存档格式、快照恢复、迁移事务、迁移日志、黄金存档与输入重放。

**范围内：**
1. 存档格式与必需元数据；格式版本与数据版本分离。
2. 世界与 Mod 数据分区、数据所有权与隔离。
3. 兼容性判定模型（四类结论 + 机器可读原因码）。
4. 迁移器合同、迁移链、迁移前验证、迁移事务与原子提交。
5. 备份与恢复；故障注入验证。
6. 正常保存/加载的一致快照边界。
7. 损坏与未知版本保护、诊断。
8. 自动化测试、故障注入与历史存档回归（黄金档 + 输入重放差异定位）。
9. **GAP-24（`DeterminismViolation` 检测）、GAP-25（`MigrationError` 检测）随本阶段落地**（C-2）。

**不在范围（本阶段明确不做，见 §八）：** 联机（P5）、SDK/Launcher（P6）、安全/性能规范与 300+ 基准（P7）、原生模块、热加载、Kernel 语义变更。

## 五、第一项实施任务：P4-01 = `SAVE-001`（存档 Manifest 与版本模型）

- **模块：** 新建 `crates/save-manager`（工作区成员）——`Project Architecture v1.0.md` §3.6 已定义 `platform/save-manager`，且明确"workspace members 可按契约增量加入"（Architecture 第 190–192 行）。**不得放入 `kernel-core`**（§3.1/§16.3 禁止）。**载体形态已裁定为 `crates/save-manager`（GK-P4-00-FIX-03，R-12）；依赖方向为 `save-manager → kernel-core`（R-13）。**
- **前置依赖：** 需先完成 **P4-00 规范交叉审查**（§九）；无其它实现依赖。
- **可改目录：** `crates/save-manager/`（新建）、`crates/save-manager/tests/`、`schemas/`（新增 `save-manifest-v1.schema.json`）、根 `Cargo.toml`（workspace `members` 增加一项）。**不改** Kernel、Mod 平台、既有 Schema、既有测试、既有规范。
- **遵循规范：** Save 规范 §3（存档文件设计）、§3.2（必需元数据）、§3.3（示例）、§3.4（格式/数据版本分离）；Architecture §3.6/§7；planning/06 门禁。
- **实施要求：**
  1. 定义存档 Manifest 数据模型与必需元数据：`save_format_version`、`save_id`、`created_at`、`last_saved_at`、`platform_version`、`game_definition{id,version}`、`kernel_api_version`、`logical_tick`、`world_schema_version`、`mods[{id,version,schema_version}]`、`simulation_config`、`integrity{algorithm,root_hash}`（§3.2/§3.3）。
  2. 明确区分 Save Format / World Schema / Mod Schema / Platform / Kernel API / Mod 六个版本（§3.4）；`game_definition` 为**元数据字段**、不并入版本集合（§3.4 说明）；`Platform Version` 涵盖 `Runtime version`，不另设字段。
  3. 发布 JSON Schema（Draft 2020-12，`additionalProperties:false`）；Schema 校验与 Rust 语义校验**双轨**；错误使用**稳定码 + JSON Pointer 字段路径**（文案不作为协议）。
  4. **本包不做 I/O**：仅内存模型 + 序列化/反序列化 + 校验（对齐 GK-P3-01 对 Manifest 的处理方式）；不读写磁盘、不涉及备份/迁移执行。
  5. `root_hash` **不在本包生成**（属 SAVE-003）；本包仅承载字段，并在缺失/占位时**拒绝**（不得把示例占位值当有效结果，§3.3）。
- **接口契约（首包冻结）：**
  - `SaveManifest`：serde 数据模型，字段与 §3.2/§3.3 一致。
  - `validate_manifest(&SaveManifest) -> Result<(), SaveManifestError>`：稳定错误码，含字段路径。
  - `SaveManifestError`：稳定码集合（如 `save.invalid_manifest` / `save.missing_field` / `save.unsupported_format_version` / `save.invalid_mod_entry` / `save.duplicate_mod_id`；具体命名在实现时冻结并纳入契约测试）。
  - `SaveFormatVersion` 与"当前平台支持的最高格式版本"的比较（§12.2 未知未来版本判定的基础）。
  - `to_bytes()` / `from_bytes()`：确定性序列化，往返逐字节一致。
  - 内置 Schema 常量 + 加载校验（Schema 缺失/非法 → 独立稳定码）。
- **测试要求：**
  - **单元：** 往返一致；必填缺失、未知字段、非法 ID/版本/时间戳、空 Mod 列表、重复 Mod ID、非 SemVer 均拒绝；Schema 与 Rust 校验结果一致；错误码与字段路径稳定。
  - **Schema：** Draft 2020-12 元校验；示例 Manifest 通过；错型输入被拒绝。
  - **确定性：** 不引入磁盘/网络/系统时间依赖。
- **验收标准：**
  1. Save Manifest JSON Schema 发布且与 Rust 模型一致。
  2. 必需元数据齐备，版本分离语义明确。
  3. 校验错误机器可读、含字段路径。
  4. 缺失/占位 `root_hash` 被拒绝（不冒充有效校验）。
  5. 本地门禁全绿（命令见 §六），CI 由 Gitee Go 触发。
  6. 文档明确标注"仅模型与校验，无 I/O / 摘要 / 迁移"。
- **交付报告：** 按 `planning/06` §7 模板。

## 六、测试命令、失败处理与原档保护

- **测试命令（既有入口，逐字执行）：** `cargo fmt --all -- --check`；`cargo clippy --workspace --all-targets -- -D warnings`；`cargo test --workspace`；`cargo run -p game-platform -- demo`。（CI：Gitee Go 流水线 `game-kernel-rust-ci`，push `main` 触发。）
- **失败处理（Save 规范 §9.3/§15.3）：** 不得把临时数据标记为正式存档；不得覆盖唯一可恢复原档；保留错误码与失败步骤；确认原档仍可恢复；提交不确定时用提交日志 + 摘要判断，不重复执行有副作用的迁移。
- **原档保护（§9.1/§10/§11.2/§15.4）：** 迁移不得直接在唯一原档上做不可恢复修改；保存失败不得覆盖最近一次确认成功的正式存档；未知数据不得静默清空；故障注入逐例验证原档可恢复。
- **首包说明：** `SAVE-001` 为**纯内存**，不触碰任何磁盘存档——**原档保护在 SAVE-001 无落地风险**，§六规则自 `SAVE-002` 起生效。

## 七、与 Mod 版本变化 / 旧存档兼容的边界条件

- **版本分离：** Mod 版本变化 ≠ 数据结构变化；迁移必须以 **Schema 版本**为依据（§3.4）。
- **新增 Mod：** 能否加入旧存档由 Compatibility Resolver 判定（§6），**不得自动绕过**兼容性检查（§15.4）。
- **更新 / 移除 / 替换 Mod：** 须有明确转换合同，否则阻止（§7）；移除拥有持久化数据的 Mod 不得静默丢弃数据。
- **跨 Mod 引用失效：** 必须可检测，**不得自动改指**（§4.3）。
- **未知未来格式：** 高于支持版本的存档**禁止普通写入**（§12.2）。
- **降级：** 不自动推断逆向迁移；需已验证逆向迁移或从备份恢复（§8.2）。
- **与确定性/重放：** 迁移必须确定性（§8.4）；**GAP-24 检测落地前，不得声称运行期可判定确定性违规。**
- **重放边界（F-8，GK-P4-00-FIX-03）：** P4 的"重放"仅指**同一确定性边界内的回归重放**（黄金存档 + 输入重放以定位差异）；**跨版本/跨平台重放属独立能力，不在 P4 范围**（`Kernel Contract v1.0.md` §10/§14；存档兼容不蕴含重放兼容）。
