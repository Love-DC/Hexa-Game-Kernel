### 1.2 规范对迁移的强制性条款（【契约明示】）

- §8.1：迁移器声明 12 字段（唯一 ID、所属 Mod、源/目标 Schema 版本、迁移器版本、所需依赖、输入/输出数据范围、是否修改世界数据、是否不可逆、资源预算、迁移验证方法）；并明示「实际迁移代码、参数格式和运行 ABI 必须由平台实现规范补充」——**该实现规范当前不存在**。

- §8.5：迁移前验证 9 步（完整性、源 Schema、迁移链、权限、资源预算、磁盘空间、生成迁移计划、创建恢复点、记录原存档标识和摘要）。
- §9：迁移事务、失败处理、原子提交——按 `planning/22` L89 归 SAVE-007。
- §15.1：单元测试须覆盖迁移链查找、迁移循环检测、迁移计划生成。

## 2. 目标与非目标

### 2.1 目标（本提案建议的 SAVE-006 范围）

1. 迁移器描述符数据模型与内存注册表（声明校验、唯一性、冲突拒绝）。
2. 确定性迁移链查找（缺失/循环/歧义/不兼容步骤检测），输出对齐 SAVE-005 已冻结的 `MigrationPath`。
3. 不可变、可审查的迁移计划构建（§8.5 步 7 的归属建议，见 §7）。
4. GAP-24/25 在本包**可落地部分**的实现与**不可落地部分**的缺口登记（见 §8，不虚报关闭）。
5. 错误类型、稳定码与契约测试矩阵。

### 2.2 非目标（明确不做）

- 迁移器执行、数据转换、事务、原子提交、崩溃恢复、原档回退（SAVE-007）。
- 备份/恢复与故障注入框架（SAVE-008）；Mod 增删替换策略（SAVE-009）；跨 Mod 引用分析（SAVE-010）；诊断渲染（SAVE-011）。
- 迁移器代码的加载与运行 ABI（规范明示由平台实现规范补充，本阶段不定义）。
- 修改 SAVE-001~005 任何已冻结代码、测试或公开签名；新增依赖；修改 `Cargo.toml`/CI；修改 `kernel-core`/`platform-core`。
- 关闭 GAP-24/25（二者由 SAVE-012 验收，见 §8）。

```rust
pub struct MigrationDataScope { pub world: bool, pub mods: BTreeSet<String> }
// mods 为空且 world=false ⇒ 仅 owner 自身数据；声明触及他 Mod 数据不构成本包拒绝理由
```

【推导建议】「仅承载不解释」原则与 SAVE-005 B-1（Mod version 不作谓词）一致：本包只对注册与链查找所必需的 5 个字段做判定，其余字段进入迁移计划与诊断记录，避免本包语义膨胀。

### 3.4 数据范围声明的三层语义区分

为避免把「声明」误当作「行为」，明确区分：

1. **规范明确禁止的行为**：迁移器**执行时**访问其他 Mod 的私有存储空间（§8.4）。这是运行期约束，SAVE-006 无法静态检测，归 GAP-24(c) 与 SAVE-007 执行环境。
2. **受控接口读取**：若未来存在受控、明确授权的跨 Mod 数据读取接口，其访问不属于「私有存储」范畴。该接口当前不存在，属规范外扩展。
3. **描述符声明**：`input_scope` / `output_scope` 中的数据范围声明是**元数据**，表示迁移器作者声明其意图触及的数据域。声明本身不违反 §8.4；只有当执行时实际访问了未授权的私有存储才构成违规。

因此，SAVE-006 对 `input_scope` 声明涉及他 Mod 数据范围的处理是：**仅承载、不拒绝、不解释**。是否对此类声明施加额外注册约束（如要求显式审批标记），现有规范未明确，标为【待裁决 D-3e】。

## 4. 注册表与冲突规则【待裁决 D-2】

### 4.1 推荐方案

```rust
pub struct MigrationRegistry { /* 内部 BTreeMap 索引，构建后不可变 */ }

impl MigrationRegistry {
    /// 全量校验后构建；同一输入集合无论顺序产出同一注册表。
    pub fn build(descriptors: Vec<MigratorDescriptor>)
        -> Result<Self, MigrationRegistryError>;
}
```

- **主键唯一性**：`migrator_id` 全局唯一；重复 ⇒ `DuplicateMigratorId`。
- **边唯一性**：同一 `(domain, from_schema, to_schema)` 只允许一条已注册迁移器；冲突 ⇒ `ConflictingMigrationEdge { existing_id, new_id }`。
  - 理由：边唯一是链查找确定性的结构性前提——同一对版本间存在两条边必然歧义，把该歧义从查找期提前到注册期拒绝，符合「选择必须确定且可记录」（§8.3）。
- **声明校验**（构建期全量、确定性顺序报告）：`EmptyMigratorId` / `EmptyOwnerModId` / `InvalidVersionFormat { field, value }` / `IdentityEdge { version }`（`from == to` 无意义拒绝）。
  - `from > to` **不拒绝**：§8.2 允许显式声明的逆向迁移器，禁止的只是「自动推断」。
- **不依赖注册顺序**：内部一律 `BTreeMap` 存储，查找遍历按 `(to_schema, migrator_id)` 字典序；注册输入顺序对构建结果与查找结果均不可观察。契约测试以随机置换输入断言结果逐字节一致（§10 T-8）。
  - 理由：装配层从多个 Mod 包聚合描述符，聚合顺序取决于包枚举顺序等环境偶然因素；若结果依赖注册顺序，则同一存档在不同环境下判定不同，违反 §5.2「判定结果必须可重复」与 §8.3「确定且可记录」。

### 4.2 备选与代价

- 备选 A：允许同边多迁移器、查找期按某规则择优——**否决**：把确定性寄托于排序规则不如注册期拒绝直白，且 §8.3 对「歧义」的字面态度是停止。
- 代价：同一 Mod 对同一版本跨度的并行迁移实现无法共存；如有真实需求，须由 Mod 作者合并为单个迁移器。可接受。

## 5. 迁移链查找算法【待裁决 D-3】

### 5.1 图模型与输入

- 图：按 `MigrationDomain` 分域的有向图；节点 = `SaveFormatVersion`；边 = 已注册迁移器（注册期已保证同 `(from,to)` 唯一）。
- 查询：`find_path(domain, from, to) -> Result<MigrationChain, MigrationLookupError>`。
  - 起点 = 存档记录的该域 `schema_version`（SAVE-005 步 6 已识别差异）；终点 = 当前环境该域的 `schema_version`。
  - **终点来源**：Mod 域由装配层自 platform-core `ModManifest` 转换注入（既有 SAVE-005 信息流）；**World 域的「当前世界 Schema 版本」无权威来源**（§1.3，`planning/28` §2.4），必须由装配层显式注入——本包不读取 crate 常量或环境。该注入要求写入契约，并标注候选 GAP-27 未关闭。

### 5.2 算法（推荐）

1. `from == to`：调用方不应查询（SAVE-005 仅在差异时查）；若发生，直接返回空链（等价 `NotRequired` 语义）。
2. 自 `from` 起按字典序 DFS 枚举简单路径（节点不重复）至 `to`。每扩展一步即检查当前迁移器的 `requires`：若不满足，该分支剪枝，不计入有效路径（剪枝只减少搜索空间，不改变有效路径集合——被剪掉的分支本就不满足有效路径定义）。
3. **有界收集**：设诊断收集上限 `DISCOVERY_LIMIT = 3`。收集有效路径至 `found`，当搜索空间穷尽、或 `found.len()` 达到 `DISCOVERY_LIMIT` 时停止。
   - **歧义可提前确定**：`found.len()` 达到 2 时歧义判定已成立；继续收集第 3 条仅为诊断证据，不改变结论。
   - **唯一性与缺失须穷尽**：`found.len() < 2` 时算法不因收集上限而停止——唯一路径（收集 1 条）与无路径（收集 0 条）的结论均以搜索空间穷尽为前提。
   - **触达上限 ≠ 完备**：`found.len()` 达到 3 即停止时，算法尚未检查是否还存在第 4 条有效路径，故候选链的**完整性未知**。
4. 计数定结论：
   - `found.len() >= 2` ⇒ **`AmbiguousMigrationPath`（拒绝）**；
   - `found.len() == 1`（搜索已穷尽）⇒ `Ok(chain)`；
   - `found.len() == 0`（搜索已穷尽）且存在不兼容路径 ⇒ `IncompatibleStep`（诊断优于裸缺失）；
   - `found.len() == 0`（搜索已穷尽）且无任何候选 ⇒ `NoMigrationPath`（缺失）。

**诊断字段语义**：`AmbiguousMigrationPath` 携带 `discovered_chains`（≤3 条，按 hop 序列字典序）与 `truncated: bool`。
- `truncated = true`：搜索因达到收集上限（3 条）而停止，**候选链完整性未知**；**这不代表已证明存在第 4 条路径**，仅代表搜索未穷尽、必然还存在未检查的分支。
- `truncated = false`：搜索空间已穷尽，所列 `discovered_chains` 即**全部**有效路径（此时有效路径数不超过收集上限，故被完整枚举）。

**不设「全部候选总数」字段**——有界收集下无法准确计算总数，已发现数量不得冒充总数。

### 5.3 关键规则的依据与边界

- **多路径 ⇒ 歧义拒绝（推荐）**：§8.3 明示「歧义必须停止」，且未规定任何择优规则（最短/最新/注册序均无规范依据）；在规范沉默处自行择优等于发明规则。代价：合法的多实现并存场景被拒绝，须由注册方（Mod 作者/装配层）消解——与 §8.3「停止」语义一致。【推导建议，待裁决确认】
- **循环的落实**：§8.2 允许显式逆向迁移器（如 `1.0→2.0` 与 `2.0→1.0` 并存），故**含环图本身合法**，注册期不得拒绝；「链存在循环必须停止」落实为：①选中的链为简单路径、构造性无环；②环导致的 ≥2 条简单路径按歧义拒绝；③环若不构成多路径则不阻断（诊断可选）。**不设独立 `CycleDetected` 错误**——避免与 §8.2 显式逆向冲突。该解读属【推导建议，待裁决确认】。
- **跨 Mod 迁移**：本包链查找仅在单一 `MigrationDomain` 内进行；`input_scope` 声明触及他 Mod 数据仅作承载，不开启跨域链查找（跨 Mod 数据转换属 §7.3 替换合同，归 SAVE-009/010）。【推导建议】
- **单边跨版本**：允许（`1.0 → 4.0` 一条边合法）；方向必须显式；不限制跨度。依据 §8.1/§8.2 未设限制。
- **复杂度边界与风险登记**：迁移图是有限图（节点数 = 已注册的不同 Schema 版本数，边数 = 迁移器数）。**歧义判定可提前确定**（第 2 条有效路径出现即成立）；但**唯一路径与无路径的证明以搜索空间穷尽为前提**，在病态大图（大量版本节点 + 稠密边 + 长链）下仍可能产生指数级搜索量——`requires` 剪枝只减少搜索空间、不改变有效路径集合，也不改变这一最坏情况。本提案**不引入搜索预算**：理由（a）实际迁移图预期极小（Mod Schema 版本链通常为线性或近线性）；（b）预算会引入「预算耗尽」新失败模式，且按纪律不得报为 `NoMigrationPath`，须新增独立稳定码；（c）SAVE-006 阶段无性能证据支持其必要性。**该风险未完全解决**，登记为【待裁决 D-3g】：若负责人要求引入预算上限，须同步批准独立稳定码 `save.migration.search_budget_exceeded` 及其语义（预算耗尽 ≠ 无路径 ≠ 歧义）。

## 6. 歧义、循环、缺失及不兼容处理（汇总语义）

| 情形 | 结论 | 稳定码（建议，§9） |
|---|---|---|
| 重复 `migrator_id` | 注册失败 | `save.migration.duplicate_migrator_id` |
| 同域同 `(from,to)` 边冲突 | 注册失败 | `save.migration.conflicting_edge` |
| 非法声明（空 ID / 版本格式 / 自环边） | 注册失败 | `save.migration.invalid_descriptor` |
| 无任何候选路径 | 查找失败（缺失） | `save.migration.no_path` |
| 候选均因 `requires` 不满足而不可用 | 查找失败（不兼容步骤） | `save.migration.incompatible_step` |
| ≥2 条有效路径（含环导致的多路径） | 查找失败（歧义） | `save.migration.ambiguous_path` |
| 唯一有效路径 | 成功 | — |

诊断规则【推导建议】：错误消息含域、from/to、候选信息（`discovered_chains` ≤3 条 + `truncated` 标记，字段语义见 §5.2：`truncated=true` 表示因触达收集上限而停止、完整性未知，`truncated=false` 表示已穷尽、所列即全部有效路径）；一切集合输出确定性排序；文案不作为协议（沿用 SAVE-001 先例）。搜索预算耗尽不构成本包错误；若未来引入预算（D-3g），须以独立稳定码 `save.migration.search_budget_exceeded` 报告，不得混入 `no_path` 或 `ambiguous_path`。

## 7. 迁移计划与 SAVE-007 接口【待裁决 D-4】

### 7.1 归属建议

- **SAVE-006 负责「计划构建与链验证」**：产出不可变 `MigrationPlan`——这是 §8.5 步 7「生成迁移计划」与 §15.1「迁移计划生成」测试要求的落点。
- **SAVE-007 负责执行面**：调用迁移器、数据转换、临时副本、事务、提交日志、原子提交、失败回退与原档保护。
- 依据：§8.5 的 9 步中，步 1-3（完整性/源 Schema/链验证）已由 SAVE-005/006 覆盖；步 4-6、8-9 的执行与资源属性属 SAVE-007/008；步 7 是纯数据产物，与链查找共享同一图与输入，放在 SAVE-006 可使「判定 ⇒ 计划 ⇒ 执行」三段各自可测试、可冻结。

### 7.2 计划内容（建议）

```rust
pub struct MigrationPlan {
    pub save_id: String,                 // §8.5 步 9：原存档标识
    pub source_root_hash: String,        // §8.5 步 9：原存档摘要（引用 SAVE-003 值）
    pub steps: Vec<PlannedMigration>,    // 全局有序：先按域字典序，域内按链序
    // PlannedMigration = { domain, migrator_id, from_schema, to_schema,
    //                      changes_world_data, has_irreversible_ops,
    //                      resource_budget, verification }（描述符快照）
}
```

- 计划构建纯函数：同一注册表 + 同一 `InspectedSave` + 同一目标版本集合 ⇒ 计划确定性序列化逐字节一致（serde JSON，风格同 SAVE-001）。
- 计划**只含已验证信息**：每步描述符快照随计划冻结，SAVE-007 执行时不再信任注册表外信息。
- 计划持久化（写入提交日志）归 SAVE-007；本包只定义内存模型与序列化。

### 7.3 与已冻结 `MigrationHop` 的关系

- `MigrationHop { from_version, to_version, migrator_id }` 足以作为**判定报告中的路径摘要**（SAVE-005 用途），但不足以作为**执行计划**（缺预算、验证方法、不可逆标记、域归属）。
- 【推导建议】**不扩展** `MigrationHop`；新增独立 `PlannedMigration` / `MigrationPlan` 类型承载执行元数据；`MigrationPlan.steps` 与注入 SAVE-005 的 `Available(Vec<MigrationHop>)` 由同一查找结果派生，契约测试断言二者链序一致。
- 若负责人认为应统一类型，代价是触动 SAVE-005 已冻结公开签名（含 BOX-DECISION-01 留痕文档的再修订），**不推荐**。

### 7.4 查找失败与 SAVE-005 判定器的映射

SAVE-005 接口仅三值，无法表达歧义/不兼容细分。建议映射【待裁决 D-4b】：

- 方案①（推荐）：`NoMigrationPath` / `AmbiguousMigrationPath` / `IncompatibleStep` 均由装配层映射为 `MigrationPath::Unavailable` 供判定器（判定语义 = 无可用路径，原因码 `schema_mismatch_no_migration`）。
  - **信息损失说明**：`AmbiguousMigrationPath`（有路径但歧义）与 `IncompatibleStep`（有路径但依赖不满足）在 SAVE-005 机器可读层面均被统一报告为 `schema_mismatch_no_migration`（Schema 不匹配且无可用迁移）。这不精确——二者并非「无迁移」，而是「无**可用**迁移」。但 SAVE-005 的 11 原因码已冻结，无更精确码可用。
  - **诊断保留**：详细 `MigrationLookupError`（含歧义候选、缺失依赖）由装配层保留并传递给诊断层（SAVE-011），不进入 SAVE-005 的 `CompatibilityReport`。
  - **代价**：接受机器可读诊断的近似性，换取 SAVE-005 冻结面零改动。若负责人认为不可接受，唯一替代是修订 SAVE-005 契约新增原因码，代价是重新验收 SAVE-005，**不推荐**。
- 方案②：装配层在判定前短路、直接产出 Blocked 结论——绕过判定器，破坏 §5.3 步序单入口，不推荐。

## 9. 错误类型、稳定码与 I/O 纪律【待裁决 D-6】

### 9.1 错误与稳定码（建议草案）

```rust
pub enum MigrationRegistryError {   // 构建期，save.migration.*
    DuplicateMigratorId { id: String },
    ConflictingMigrationEdge { domain: MigrationDomain, from: SaveFormatVersion,
                               to: SaveFormatVersion, existing_id: String, new_id: String },
    InvalidDescriptor { id: Option<String>, field: DescriptorField, reason: String },
}

pub enum MigrationLookupError {     // 查找期，save.migration.*
    NoMigrationPath { domain: MigrationDomain, from: SaveFormatVersion, to: SaveFormatVersion },
    AmbiguousMigrationPath { domain: MigrationDomain, from: SaveFormatVersion,
                             to: SaveFormatVersion,
                             discovered_chains: Vec<Vec<String>>, // ≤3 条，每条为 hop 的 migrator_id 序列，按 hop 序列字典序
                             truncated: bool },                    // true=因触达收集上限(3条)而停止、候选链完整性未知（非"已证明存在第4条"）；false=搜索已穷尽，discovered_chains 即全部有效路径
    IncompatibleStep { domain: MigrationDomain, from: SaveFormatVersion,
                       to: SaveFormatVersion, unsatisfied: Vec<(String, String)> }, // (migrator_id, 缺失依赖) 字典序
}
```

- 命名空间 `save.migration.*`，与 `save.compat.*` 风格一致；手工 `Display`/`Error` 实现（writer.rs 先例）；确定性排序写入契约。
- 【待裁决】Save 规范 §13 有示例码 `SAVE_MOD_REQUIRED_MISSING` 仅为示例不约束命名（planning/33 已确认先例）；本码表待冻结。

### 9.2 I/O 纪律

- `migration.rs` **纯内存、零 I/O**；注册、查找、计划构建均为纯函数。
- 迁移器声明的**读取**归装配层：Mod 包 `migrations/` 目录与清单由 platform-core/装配层解析（Mod Platform 规范 §4：未在清单声明的文件不得自动执行），转换为 `MigratorDescriptor` 后注入。
- DC-10 白名单**不扩展**；契约测试沿用 dependency_boundary 扫描断言本模块无 fs/net/env 引用。
