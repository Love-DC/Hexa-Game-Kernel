## GK-P3-05 原子注册风险调查（只读，结论：预校验后逐个注册可保证零半注册）

- **`Kernel::register_system` 完整实现**（`crates/kernel-core/src/lib.rs:521-531`）：① `validate_type_id(&id)` 失败 → `InvalidSystemId`；② 遍历 `self.systems` 查重 → `DuplicateSystemId`；③ `self.systems.push`；④ `sort_by(id)`。**两条失败路径都在 `push` 之前**，返回 Err 时**未改变 Kernel 状态**。
- **`validate_type_id`**（行 837-851）：仅允许 `[a-z0-9._/-]`、非空、不以 `/` 开头/结尾、不含 `//`、≤128 字符。**纯函数、无副作用**。
- **唯一状态**：`Kernel { world, systems: Vec<Box<dyn System>>, fault }`，`systems` **私有**；无 unregister / 批量注册 / `systems()` 访问器 / 回滚 API（全仓仅 4 个调用点：main.rs×2、p1 测试×2）。`KernelErrorCode` 含 `InvalidSystemId`/`DuplicateSystemId` 可精确区分。
- **现有能力**：`from_snapshot` 构造 `systems: Vec::new()` 的空系统 Kernel（行 708-712）；`snapshot()` 只序列化 `world`（不含 systems，行 680-688）；`LoadedWasmMod::system(&self)` **每次返回全新 `WasmSystem` 值**（共享 `Arc<Module>`+`Engine`，行 1555-1562），可低成本为探针与真实 Kernel 各建一份。`System: Send + Sync`（无 Debug/Clone 约束）。
- **方案比较**：
  - **A 预校验后逐个注册**：Platform 侧先对全批调用 `validate_type_id` 等价校验 + 批内查重 + 与已有系统查重，**全部通过后**才逐个 `register_system`。因 Kernel 的失败条件与 Platform 可完全复现（同一 id 字符串、同一 `validate_type_id` 规则），预校验通过 ⇒ 后续每个 `register_system` 必成功 ⇒ **真正零半注册**。不改 Kernel。复杂度低。
  - **B 临时 Kernel 验证完整集合**：`Kernel::new(cloned world)` → 逐个 register 探针系统 → 成功后对真实 Kernel 重放。**问题**：仍需保证真实 Kernel 与探针 Kernel 的前置条件一致；若真实 Kernel 已有系统而探针没有，探针通过 ≠ 真实通过；且 `World` 需可 clone（是），但**多一份世界构建成本**且引入「探针与真实状态不同步」新风险。**不比 A 强**。

- **结论/推荐：方案 A**。理由：Kernel 的 `register_system` 失败条件完全可在 Platform 侧无副作用复现（id 字符串 + 纯函数 `validate_type_id` + 查重集合），故「预校验全过」进而在 Kernel 侧逐次注册必不失败，实现真正的零半注册，且无需改 Kernel。**注意措辞**：这是基于「注册前条件可完全复刻」的**构造性保证**，而非平台新增强制事务机制；须以契约测试断言「批次失败时已注册数=0」来证明。
